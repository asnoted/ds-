# 编码标准

`AGENTS.md` 是**房规与导航**(常驻上下文, 写它是为了让 agent 少走弯路); 本文件是
**判断题**--那种任何护栏都替代不了的跨文件一致性, 由 review agent 施加(`/code-review`
的 Standards 轴). 机械性的那类不进这里, 它们进 `pnpm quality` 与 `.husky/pre-commit`.

## 3. 文档与 scripts 不用中文标点

**规则**: **全部 `.md`** 与 **`scripts/` 下的 `.py`** 一律用半角标点.
中文标点只允许出现在**数据与产物**里(见下表).

`scripts/ascii-punct.py` 既是改它的工具, 也是查它的守卫: `--check` 接进
`pnpm quality`, 违反规矩的提交在 CI 里就红, 而不是等 review 时被人眼抓到.

### 适用范围

| 范围                                                                 | 处置 | 理由                                               |
| -------------------------------------------------------------------- | ---- | -------------------------------------------------- |
| 全部 `.md`                                                           | 扫   | 仓库的散文主体, 规则的主要对象                     |
| `scripts/` 下的 `.py`                                                | 扫   | 注释与用户可见提示语最常被读                       |
| `src/` `entrypoints/` `dsb/` `tests/`                                | 不管 | 见下"范围为什么这么小"                             |
| `.agents/` `vendor/`                                                 | 不碰 | 别人家的代码, 手改会被升级冲掉                     |
| `protocol/evidence/`                                                 | 不碰 | 真机抓下来的**原件**, 改它等于伪造录证             |
| `protocol/fixtures/` 及 `.json` `.html` `.svg` `.toml` `.yaml` `.sh` | 不碰 | 契约样例与配置, 改字面等于改字节, 会连带改测试断言 |

**范围为什么这么小**(2026-10-11 用户收窄): 早先把 `.ts` `.mjs` 也扫了, 96 个
文件里只有 9 个与功能改动重叠, 换来的是转换器得认 f-string / 三引号 / 正则
字面量三种边界, 外加一个"新文件会被漏掉"的静默 bug. 覆盖面一大, 守卫就没人
愿意维护--**那才是真失效**. 存量的 `.ts` 保持已扫不回滚(回滚要让仓库并存
两套标点, 更糟), 但不再强制.

### 字符串字面量也扫, 但要认词法状态

`scripts/` 下的 `.py` 里, 字面量中的中文标点就是产品文案, 跟注释里的没有
本质区别, 所以**扫**. 但转换器必须认词法状态 -- 一个双引号串里含中文引号
(`U+300C` / `U+300D`), 直接换掉会让字符串提前闭合, 代码当场断掉. 引号按
所在位置换: 双引号串内换成 `\"`, 单引号串内换成 `"`, 注释与三引号串换直引号.

这不是"少扫一点"的折中, 是"扫得对"的前提. 裸代码(标识符, 关键字)
一个字符都不碰.

> 举例子用**码位**而不是字面字符: 本文件自己受这条规矩管, 写出真字符会被
> 转换器换成直引号, 例子就变成自指的废话(踩过).

**有意不换**: 箭头 `→ ← ↔`, 框线 `─ │ ├ └`, 数学 `≠ ≥ ≈ ∈ −`, `✓ ★`.
它们不是标点. 框线还是 ASCII 流程图的骨架, 换成 ASCII 框线会把图画烂;
箭头与数学符号换成 `->` `!=` 会污染散文. 写在这里是为了免得下一个人
以为漏了.

### 三个真踩过的坑

- **f-string 不是单个 STRING token**(Python 3.13 起 PEP 701 拆成
  `FSTRING_START/MIDDLE/END`). 不单独认它, f-string 内容会落进"裸代码"
  分支, 引号直换 -> 字符串截断 -> 整个文件语法坏掉. `ruff` 抓到的.
- **三引号串里换直引号会提前闭合**: 结尾的引号紧贴 `"""`, 凑成四个, 字符串
  提前闭合再留下一个孤立引号. 所以三引号串用**不属于定界符**的那个引号.
- **新文件会被静默漏掉**(2026-10-11): 转换器原来用 `git ls-files` 取文件,
  而它只列**已跟踪**的 -- 但最该被转换的恰恰是**刚写出来**的文件. 本节当年
  就是这么带着中文标点进了 main, 而转换器当时报的是"干净". 现在取
  `git ls-files --cached --others --exclude-standard`: 已跟踪的, 加上未跟踪
  但没被 ignore 的; 被 `.gitignore` 挡住的(`node_modules` / `.venv` /
  `dsweb/bundle`)仍然不会进来.

### 怎么落地

- 改之前跑 `uv run scripts/ascii-punct.py`; 它幂等, 跑第二遍没改动.
- **它豁免自己**: 它的映射表键就是字面的中文标点, 被扫一遍键会变成 ASCII,
  映射失效, 工具当场变哑巴而且是**静默**的 -- 报"改好 0 个文件", 看着像
  任务已完成.
- `pnpm quality` 里的 `--check` 是硬判据, 别用"这个文件特殊"绕过.

### 来源

retro(2026-10-10). 用户直给的要求.

## 4. 解释不通就写"没摸清",别用伪解释充数

**规则**: 两件观测到的事实对不上时, **不要**写一句听起来像解释的话去
填那个空. 写"没摸清", 并说清**已经确认的是什么**,**还不知道的是什么**,
以及**什么样的实验能推翻它**.

**判据一句话: 能被证伪的才是断言.** "两个上限互不相干,没有按 token 密度
折算过" 听着像机制, 但没有任何实验能推翻它 -- 它什么也没说.

### 怎么栽的

逆向网页输入上限时, 前端字符上限 `2,621,440` 与服务端 ~98 万 token
对不上. 第一版 ADR 写的是"两个独立的上限, 互不相干, 没有按 token 密度
折算过", 还配了"可能是按别的文本密度设的"这类猜测撑场面. 那不是解释,
是把"我不知道"穿成了"我知道了".

真相比猜的便宜: 一次 `localStorage` 读就把前端的 `input_character_limit`
取到手, `dsweb/FINDINGS.md` 里记着的机制(`(len − 2621440) / len × 100`)
也是读出来的, 不是推出来的. 而**剩下那部分对不上依然没解释** -- 那就照实
写"没摸清", 别拿前半段的成功冒充后半段的答案.

### 怎么落地

- 写 ADR 的"为什么"段时, 自问一句: **有人能设计一个实验推翻这句话吗?**
  不能, 就把它从"为什么"挪到"未验证项".
- "未摸清"不是缺点, **装成已知才是**. 而且要写清已确认的现象本身
  ("两者不随文本密度对齐到同一个数"是结论), 不是只写"没摸清"三个字.
- 相关: 第 3 节末尾那条"断言要能被证伪"是同一条纪律在标点上的投影.

### 来源

retro(2026-10-10). 用户当面纠正过一次: "把没摸清如实记上, 别用独立互不相干
这种伪解释充数."

## 5. 下结论前先验那把仪器

**规则**: 任何"我测过了"的结论, **先确认测量本身成立**, 再看结果.
判据一句话: **仪器没校准, 读数就不是事实.**

### 怎么栽的(同一天三次, 同一形状)

| 我以为                                      | 实际                                                | 差点得出的错结论                                  |
| ------------------------------------------- | --------------------------------------------------- | ------------------------------------------------- |
| `typeof tools.bash === "function"` 所以能调 | 沙箱的 `typeof` **一律**返回 function, 不代表可调用 | "没有 shell" / "shell 可用", 反复猜名字浪费好几轮 |
| 注入的是全角逗号, 守卫该红                  | 注入的其实是 **ASCII** 逗号                         | "守卫坏了"                                        |
| 注入的是谚文字符, 守卫该报                  | 注入的是**汉字**                                    | "守卫坏了"                                        |

后两次的共同点更刺眼: **我在用一把坏仪器去检验一台机器**, 而机器本来是好的.

### 怎么落地

- **注入完, 先断言注入真的发生了**(比如按码点读回那一个字符), 再信守卫的判定.
  没有这一步, "没报错" 与 "守卫没抓到" 分不开.
- **自己写的探针先测它自己**: 报"没变化"的工具, 先确认它在有变化时**会**报变化.
- **工具报"没有/为空"时先问仪器**: 是真没有, 还是这个观测点看不见?
  (本仓已有同源的一条: "0 帧 / 空"不能推出"没发生", 见 AGENTS.md.)
- **不靠单一信号下结论**: 至少一个独立观测点交叉验证. 模型说"改好了"不算,
  去看磁盘; 状态说"开着"不算, 去看钩子装没装.

### 来源

retro(2026-10-11). 三次都是当天同一轮里, 且第二次与第三次在**修守卫**的
过程中发生 -- 越是"我在验证一个工具"的场合, 越容易忘了两件事: 仪器要校准,
结论要交叉.

## 6. 注释压到最低

**规则**: 代码里**几乎不写注释**. 只有三类允许:

- 非平凡的代码(为什么这么写, 而不是那么写 -- 读代码本身读不出来时)
- 函数定义: 参数与返回值不自明时
- 类定义及其成员

**判据一句话: 能从代码本身读出来的, 不写.** 名字起得好, 注释就是多余的;
名字起得差, 注释是在替名字还债, 而那笔债还不清 -- 读的人得先信注释,
再去核代码, 等于两份都要读.

### 怎么落地

- 写完先删一遍: 只是复述下一行在干什么的, 删.
- 注释留**理由**, 不留过程("先 X 再 Y 然后 Z"是流程描述, 不是理由).
- 不写版权头, 不写"作者 / 日期"栏 -- `git log` 比它准, 而且不会过期.
- 注释也会烂. 代码改了注释没跟上, 它就从"帮助"变成"误导",
  且**读的人无法分辨**哪一句已经失效. 这是压低注释数量最实在的理由.

### 来源

用户 2026-10-13 直给的英文原文(限严格最小, 几乎不写).
