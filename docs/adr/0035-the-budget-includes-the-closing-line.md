# ADR-0035: 额度要连末尾那句一起算:一页连脚注,一条结果连末句

- **Status**: accepted
- **Date**: 2026-10-17
- **Supersedes**: none

**只修订 ADR-0026 第 4 条与 ADR-0032 事实 1 各一点**,两个承诺从此真的成立.三个定案值
**一个不动**(`WORK_READ_PAGE_LINES = 200` / `WORK_READ_BYTES = 16_000` /
`WORK_RESULT_CHARS = 16_000`);改的是**这笔额度怎么花**--行与行之间的换行,末尾那句
脚注/末句,都算在里面.

## 问题

两处闸都把末尾那句**算在额度外**:

| 闸                           | 额度按什么累加                      | 交出去的那条能到多少              |
| ---------------------------- | ----------------------------------- | --------------------------------- |
| `read` 的一页(`render_page`) | 每行 `正文 + 行号 + 2`,**换行不算** | 额度 + 换行(每行 1 字) + 1 + 脚注 |
| `ls` / `grep`(`cap_result`)  | 每行 `正文 + 1`                     | 额度 + 末句                       |

实测(各造 400~1000 行):

- `read`,100 字行 / 400 行,默认页:一页 **16,154 字**.
- `read`,`limit=2000` 加 3 字行:一页 **17,939 字**--越过 1,939 字,**那是正文,不只是脚注**.
- `cap_result`,行宽 64 / 80 / 100 / 120:各 **16,041 / 16,008 / 16,009 / 16,023 字**.

而**扩展那道闸正好是 16,000**(`src/lib/continuation.ts` 的 `MAX_RESULT_CHARS`,ADR-0026
第 4 条与它同数),`truncateResult` **从尾巴上截**:截掉的正是**脚注**--`offset` 的唯一来源;
`ls` / `grep` 那边截掉的是"收窄模式 / 换个更小的目录再列"那句.于是

- ADR-0026:"一页 `read` 的结果能原样进对话,不再被腰斩" -- 这几种形状下**不成立**;
- ADR-0032:"`ls` / `grep` 一条结果 <= 16,000 字" -- 这几种形状下**也不成立**.

**为什么一直没撞上**:ADR-0027 那两档跑的是 `dsb/work.py`,平均每行 34.5 字,200 行的默认页
只有 ~7.8K 字,离 16,000 还差 7,405;`--limit 2000` 那种形状(短行,上千行)没人真跑过.
**这是贴边才咬的洞**,不是天天咬的洞.

## 决定

**把末尾那句算进额度**:两个闸都按"最终交出去的那一整条不超过额度"来花.

1. `render_page`:每收一行,先预留"这一行的换行 + 1 + 这一页脚注的**最长写法**"
   (`_page_footer_room`,按"字节预算截断"那一态的定长算),再看加不加得下.
2. `cap_result`:先算出末句的保守长度(`_result_note(总行数, 总行数, hint)`,行号位数按最大
   取),再按"行 + 末句 <= 额度"砍.
3. **四个上限都不动**(200 行 / 2000 行 / 500 字 / 16,000).贴边时**少给一行**,而不是多给
   一句--给不下的那行按 `offset` 下一次给,而脚注里正写着它.
4. **额度小到连一行都放不下时仍然给那一行**:与 `read` 那条既有取舍同一条(空页对模型最
   没用,它拿不到任何内容,连翻到哪都不知道).这条是**例外**,此时整条会超额度--只在
   monkeypatch 出来的小额度里出现,真机那四个数下够不着(一行最多 500 + 行号 + 单行标注
   - 脚注).
5. 判据是两边共用的一条:**扩展那句"工具结果已截断"在自家工作工具这条路上一次都不该出现**
   --dsb 交出的每一条结果 <= 16,000.

## Considered Options

- **把扩展那道 16,000 抬高一点**(多留一行加一句):两个数就**不同数**了,ADR-0026 第 4 条与
  ADR-0032 第 1 条都要改,而且抬高多少都得跟着 `WORK_READ_LINE_LIMIT` 走.否决.
- **只在扩展侧留头留尾,截中间**:脚注能活,但模型拿到的是**拼接过的正文**,而且 dsb 交出的
  东西仍然比它自己声明的大(内存,storage,传输都过了真身).否决.
- **把页预算写小一点**(比如 15,000)留余量:那是**把余量写死成数**,与"两个数同数"直接冲突,
  而且没人知道该留多少(要留的是换行 + 脚注,随行数变).否决.
- **只改 `read`**,把 ADR-0032 那句声称改成"<= 16,000 + 一句":两个闸同一类洞,改一半必漂
  (ADR-0032 自己的理由).否决.

## Consequences

- **两个承诺变成真的**:一页 `read` 原样进对话;`ls` / `grep` 一条结果 <= 16,000 字.`read`
  那条的测试从宽松不等式(额度 + 500 + 200)改成钉死 `<= WORK_READ_BYTES`.
- **贴边的页少一行**:`read` 一页的正文上限从"16,000 + 换行 + 脚注"收到"16,000",少掉的是
  **一行**.
- **`--limit 2000` 那种短行页不再被截**:3 字行一页 17,939 -> 15,999,脚注还在.
- **ADR-0026 真机验过的那个数不变**:13,492 字那一页远在收窄后的额度以内,同一页还是同一页.
- **两个种子的值由既有守卫钉着**,这次没动它们:`tests/test_readme_limits.py`(README 表)与
  `protocol/fixtures/read.json`(`readPageBudget`,vitest 对着同一份断言).
