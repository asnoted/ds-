# ADR-0031: 站点原生的 `/api/v0/chat/continue` 不用:它载不动工具结果,可点的那一相也不在我们的场景里

- **Status**: accepted
- **Date**: 2026-10-16
- **Supersedes**: none

本篇是票 #105 的定夺,结论**不动任何产品代码**;ADR-0014(续聊走请求体替换)与
ADR-0029(唯一限速)都**不因此改动**.

## 问题

#104 收尾时挂出的调研:催办与自动续聊现在都走"写输入框 + 按发送"这条产品路,真机反复
踩到它的代价--顶掉用户草稿(#93),发出去的正文不是等你的那条短标记(可能被打字盖掉),
以及"Enter 与发送键都没发出去".站点自己有原生的续写口 `/api/v0/chat/continue`
(`dsweb/FINDINGS.md` §7 只记了端点名),要不要换过去?

## 摸清的事实(依据都在文末的"判据"里)

1. **端点与请求体**:`POST /api/v0/chat/continue`,体是
   `{chat_session_id, message_id, fallback_to_resume}`.它与 `completion` / `regenerate` /
   `edit_message` / `resume_stream` 同在一个生成器工厂里按 `scene` 分支.体里
   **没有任何能塞载荷的字段**.
2. **触发面**:最后一条助手消息 `status === INCOMPLETE` **且**不在生成中 **且**是叶子
   (没有子分支)时,消息底部长出一颗设计系统按钮,i18n 键 `continueGenerationButton`
   ("继续生成").点之前的预检会回错误码 `CURRENT_MESSAGE_IS_NOT_A_LEAF_MESSAGE` /
   `CURRENT_MESSAGE_IS_LOCKED`.语义上它继续写的是**同一条助手消息**,不新增用户消息.
3. **真机**(两端都验到):正常写完的那一轮,那颗按钮**不在**;起一条长生成中途点停
   (消息落进 INCOMPLETE 相)后,按钮**在**.用真鼠标事件点它,`Network` 域看到
   `https://chat.deepseek.com/api/v0/chat/continue`,按钮随之消失,圆键进生成相--
   三个观测点一致.
4. **真机**(看门狗那条腿):让看门狗在"活开着 + 静默到点"那一刻真催办,同时在窗口里
   **1s 一拍只读采样**:催办落地前后那颗按钮**都不在**--催办前,上一条助手消息已收尾
   (COMPLETE);催办后,圆键已进生成相(WIP).整段采样 `continueBtn=false`.

## 决定

**不用**.两条独立的理由,任一条都足以否决:

1. **它替不了续聊主链**.续聊要送的载荷是**工具结果**,结果住在扩展与中继这一侧,只能靠
   ADR-0014 的**请求体替换**塞进下一次 `/chat/completion`;`/chat/continue` 的体里没有位置
   放它.这不是"实现麻烦",是接口形状上就不成立.
2. **它替不了催办**.它可点的那一相是"上一条回答被停下且没写完";而催办落地的两种相--
   上一轮已干净收尾(静默来自我们这一跳没造出新的一轮),或新一轮正在生成中(卡着不动)--
   **都不长这颗按钮**(真机采样为证).要靠"回答被截断"才用得上它,那个场合标记路本来就够,
   而且它照样要走"代你发言"闸与唯一限速,换不来净收益.

因此:不进动作名册,不进产品码.逆向结论与判据工具留在档案与工具链里,产品一行不改--
这也守住了"不主动扩大站点动作面"的既有口径.

## Considered Options

- **半用(催办优先点原生按钮,按钮不在再退回标记路)**:唯一的好处是不碰草稿.但实测那颗
  按钮在催办落地相里压根不在,等于给一条几乎不走的支路维护一颗按钮的定位锚,存证与
  闸/限速接线.否决.
- **全用(续聊也改走原生)**:载不动工具结果,接口形状上不成立.否决.
- **改走 `resume_stream`**:那是站点给**断流**的自愈(配置 `sse_auto_resume_timeout=3000`),
  与我们的失败不是一回事.否决.
- **只把它当"用户自己点了也认"的旁路**:不必做事;页面本来就会自己发,扩展不该插手.

## Consequences

- 三类老代价(#93 顶草稿 / marker 被打字盖掉 / 键没发出去)**留在标记路上**--原生口解决
  不了它们,别拿它当这几条的现成答案.归因与修法仍在标记路上找.
- 工具链多了一只手:`scripts/page-action.py continue-click`(CDP `Input.dispatchMouseEvent`
  发真鼠标事件,含真滚轮滚进视口),配套 `docs/probe.md` 补一条纪律--动作要发真事件,`js`
  仍**只读**,判据用两个观测点(出站请求 URL 与页面行为),`Network` 域漏抓过,一边没有
  不当成"没发生".
- **重议的触发条件**(两条都满足才值得回来):我们的续聊出现"不需要载荷"的用法(只让模型
  接着说),或者站点给 `/chat/continue` 加上了可注入的字段.届时判据仍是这两条:能不能塞
  工具结果,以及那颗按钮在不在我们出手的那一相.

## 判据(怎么自己复现)

- **静态**:`uv run scripts/page-action.py capture --codes --out captures/x` 把运行中浏览器
  里**已加载**的站点脚本存下来(跨源 CDN 上的 `main.*.js` 也拿得到;站点回 429 时
  `fetch-dsweb-bundle.py` 走不通,这条路走得通),再 grep `chat/continue`.
- **触发面**:起一条长生成中途点停,读 DOM 里 `role=button` 且文本为"继续生成"的那颗.
- **点击腿**:`uv run scripts/page-action.py continue-click`(真鼠标事件 + 真滚轮).
- **催办那一相**:`uv run scripts/watchdog-probe.py` 造出催办,同时 1s 一拍只读采样
  (`js` 查那颗按钮与圆键相).探针自己会把 `ds-/watchdog` 的短窗口留在 storage 里,
  验完记得 `storage remove --keys '[\"ds-/watchdog\"]'` 还原.
