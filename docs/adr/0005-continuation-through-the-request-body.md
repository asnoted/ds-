# ADR-0005: 续聊走请求体替换: 钥匙是短标记, 轮数有上限, 一轮可排多块

- **Status**: accepted
- **Date**: 2026-10-17
  工具结果不再作为一条可见的长消息回灌: 对话里只留一个**短标记**(首行锚 `agent:` + 一行
  "继续"), 真正给模型的正文由 MAIN world 在**出站请求体**里替换. 一条任务最多自动续 8 轮;
  一轮里模型可以排多块围栏, 各块各打一趟网关.

依据: 一次工具调用原来就是一条 `agent:` 开头的长用户消息(TOON 正文全文进对话历史), 一轮
一条, 而且这条消息是扩展自己发的 -- 风控面上最贵的就是这个. 账号在站点那边是阶梯处罚过的
(ADR-0004), "发了几条"是唯一能自己压住的行为面.

## 决定

1. **正文改走请求体**: `inject.ts` 的 `recognizeOutgoingShape` 认出出站形状, 它给出的
   `replacePending` 把那一趟出站的 `prompt`(或 `messages` 里最后一条 `user`)换成
   `buildContinuation` 组出来的正文; 对话里发的是 `CONTINUATION_MARKER`(`agent:` 锚 +
   一行"继续"). 模型侧的读法**一字未改** -- 仍是首行锚 + TOON 载荷.
2. **钥匙是短标记本身**: 替换只在"这条出站请求的正文**逐字等于**短标记"时发生
   (`src/lib/armed.ts` 的 `matchesMarker`). 归一化只放宽两处: 换行统一(CRLF/LF), 去首尾
   空白; 其余字符严格相等. 用户手打的话原样放行并撤销武装.
3. **武装状态机三态**: `idle` / `armed`(有 TTL) / `pending`(无 TTL, 等用户按发送).
   武装在**出站窗口放行那一刻**才挂上(入队到开窗有几秒, 期间用户可能自己在发消息), 且
   **一次即作废** -- 替换没成也作废: 宁可少一轮, 也不能把用户的真消息当成续聊那趟.
4. **期限只收敛悬挂态**: `ARMED_TTL_MS = 10_000`. 钥匙落地后时间不再是安全判据(用户手打的
   那条必然不等于标记), 所以 10 秒纯粹是为了别让悬挂态挂太久; `pending` 态没有期限.
5. **轮数上限 `MAX_CONTINUATION_ROUNDS = 8`**(`src/lib/rounds.ts`): 到顶就停手 -- 这一轮
   不发, 计数归零, 记一笔失败留痕(环节 `rounds`). 答复里没有围栏就算任务收尾, 轮数归零.
6. **结果截断 `MAX_RESULT_CHARS = 16_000`**(`src/lib/continuation.ts`): 与 dsb 交出的一页
   `read` **同数**(ADR-0010), 所以一页 `read` 的结果能原样进对话, 不再被腰斩. 截断处写明
   "已截断"与原长 -- 让模型知道它看到的不是全文.
7. **一轮多块**: `parseSendFences` 按出现顺序取出所有块(`parseSendFence` 只取第一块, 留给
   "有没有排围栏"这类判据). **执行侧一趟一块**(不是一个请求塞多块: 扩展对在途 fetch 的保活
   与超时是**按请求**算的, 多块挤一趟, 几件慢工具叠起来先撞扩展的超时, 报出来还是没信息量的
   "中继不可达"). 结果拼成一段: 一块时**工具正文原样交**(不加头尾); 多块时每块前面写一行
   `工具 <名字>:`. 一轮上限 `MAX_CALLS_PER_ROUND = 8`, 排多了先执行前 8 块, 剩下的在正文里
   说明"下一轮再排". **排坏的块也占一块**(回 `MALFORMED_CALL_HINT`), 只有连不上中继才整轮
   作废.
8. **答复认 id**: 排 `call` 时记下 id, 收 `result` 时**只认自己排出去,还没收过的那一个**
   (`src/lib/fencecalls.ts`), 别的丢掉并在控制台留一行. 一轮一次 -- 重放与重投一并挡住;
   名单 FIFO 有界(16 个), 漏掉的答复挤掉最老的.
9. **不用站点原生的 `/api/v0/chat/continue`**: 它体里没有能塞载荷的字段(续聊要送的是工具
   结果), 而它可点的那一相(上一条助手消息 `INCOMPLETE` 且是叶子)也不在催办落地的那两相里.
   不进动作名册, 不进产品码; 逆向结论与判据工具留在工具链里.
10. **静默催办与刹车是两套闸**: 刹车停的是"扩展自动往下续", 催办是"15 分钟没动静就替用户说
    一句'继续'", 后者受"代你发言"闸拦(ADR-0006).

## Considered Options

- **照旧回灌长消息**: 历史里全是机器痕迹, 每条还都是扩展自己发的. 否决.
- **只把文案改短, 不动请求体**: 机器痕迹照样留在历史里, 也没碰到"量的来源". 否决.
- **把截断放到中继**: 中继只交结构化结果, 编码与呈现归扩展(ADR-0002); "给模型看多少"属
  扩展侧. 否决.
- **只放宽回灌上限, 不加翻页**: 模型能看到更多, 但一次仍只能看开头. 否决(翻页见 ADR-0010).
- **一个请求带多块**: 超时与保活按请求算, 慢工具一叠就误报"中继不可达"; 而且中继那一侧一次
  `tools/call` 就是一件工具. 否决.
- **不设轮内上限**: 一轮能跑几十件工具, 续聊刹车(按轮计)管不到轮内. 否决.
- **一块排坏整轮作废**: 模型看不到别的块的结果, 还得重排一遍. 否决.
- **一律加 `工具 <名字>:`**: 单块的正文会被我们加的头污染, 而工具的原文(包括它自己报的错)
  本来就该原样给模型. 否决.
- **只调小 TTL**, **武装后短暂禁发用户消息**, **只在请求带我们注入的 header 时才替换**,
  **记下武装时刻比时间戳**: 四条都治不了"用户在武装期内手打一条"这一件事 -- 判据必须是
  那条请求的正文本身. 否决.
- **半用(催办优先点原生"继续生成"按钮, 按钮不在再退回标记路)**: 实测那颗按钮在催办落地的
  相里压根不在, 等于给一条几乎不走的支路维护一颗按钮的定位锚, 存证与闸/限速接线. 否决.
- **续聊也改走原生**: 载不动工具结果, 接口形状上不成立. 否决.
- **改走 `resume_stream`**: 那是站点给断流的自愈(`sse_auto_resume_timeout`), 与我们的失败
  不是一回事. 否决.

## Consequences

- **可见的用户消息从"一轮一条 TOON 全文"降到"一轮一个两行标记"**; 工具结果只在模型那儿,
  不进可见流.
- **同样一件活儿, 轮数(= 出站次数)可以降到三分之一甚至更低**.
- **站点改发消息的形状, 替换就落空**: 那一轮作废(控制台留一行"没能替换进去"), 不猜, 也不
  退回长消息. 钥匙落地后又多一种成因: 正文不等于标记(可能被打字盖掉).
- **`wait.reply` 等到的现在是那条短标记**而不是载荷正文.
- **"结果没送到模型手上"与"中继没连上"是两件事**: 前者只在控制台与失败痕里看得见
  (ADR-0008), 后者照旧不进对话流, 图标翻红.
- **`protocol/fixtures/fence.json` 的字段是 `expectedCalls`(数组)**, TS 与 pytest 两处
  schema 同步改 -- 少改一处, 门就红.

## 判据(怎么自己复现)

```sh
pnpm vitest run src/lib/continuation.test.ts src/lib/armed.test.ts \
  src/lib/fenceround.test.ts src/lib/fencecalls.test.ts
```

`continuation.test.ts` 里钉着"两边同数"那条不等式, 别让它悄悄回去. 真机那些轮次(整页
13,492 字原样进对话, 围栏 1 条对 `agent:继续` 恰好 1 条)见 `docs/evidence/continuation.md`;
原生 `continue` 的两端采样见 `docs/evidence/native-continue.md`.

## 未验证项

- **站点出站的正文是否**逐字**等于我们写进输入框的短标记**: 这是钥匙的**实现前置** --
  若不等(前后空格与换行之外的任何变化), 替换恒不生效, 续聊全断. 真机上验过若干轮都成立,
  但站点改一次输入处理就会失效, 而失效表现为"每一轮都作废".
- **一轮里用户插话与在途回灌的顺序**: 单来回下队列恒一个元素, 多块下的顺序仍按"谁先入队".
