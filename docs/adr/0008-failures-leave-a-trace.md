# ADR-0008: 失败必须留痕; 发送类失败当场留一帧

- **Status**: accepted
- **Date**: 2026-10-17

图标翻红之后还得查得出**为什么**, **几点红的**, **多久自己绿的**. 中继在 stderr 上记一行
带时间戳的业务事件(`dsb/log.py`), 扩展把每次翻红写进 `storage.local`(时刻 / 环节 / 原因,
绿了再补恢复时刻), 悬停在绿着的时候回看一句, 选项页"上次故障"读同一份. 两边都**不记问题与
答复正文**; 发送类失败还**当场留一帧**页面像素.

依据: 图标红过又自己绿了, 用户问"为什么红" -- 浏览器控制台没开着就什么都没有, service worker
一重启连挂在内存里的原因也蒸发了. 事后没人答得出, 跟没设计日志一样.
另有一类更要命的: 自动续聊的每一跳失败原先只有一行 `console.log`, 不翻红, 不进存储 -- 页面
里没有新助手消息(用户以为站点卡住了), 模型没拿到工具结果(它以为工具挂了), **图标一片绿**.

## 决定

1. **两边各记一笔, 都不记正文**: 中继在 stderr 上记一行带时间戳的业务事件
   (`dsb/log.py` 的 `log_event`); 扩展把每次翻红写进 `storage.local`(时刻 / 环节 / 原因, 绿了
   再补恢复时刻).
2. **正文进不来靠签名, 不靠自觉**: `log_event` 只收具名字段, 调用点写不出 `question=`;
   异常只留类型名不带 message(消息里可能嵌着用户的东西). `log_message` 照旧整个关掉.
   扩展侧同一把签名: 失败短句由常量给出, 调用点写不出问题, 答复, 工具结果或用户消息.
3. **同一次故障只记一笔**: 最前面那条还没恢复时, 不管这次是哪个环节哪个原因都视为同一段红着
   的时间在延续 -- 否则探活每 30s, 轮询每 3s 各失败一次, 几秒就能把配额刷满, 真正要看的
   前因后果全被冲掉. 留下的是故障**开始**的时刻. 配额 `FAILURE_LOG_CAP = 20`.
4. **事件名固定, 两张册子**: 中继侧记失败与慢的那几条 -- `bad-request`(请求不合形) /
   `mcp-broke`(服务层漏接) / `tool-broke`(处理器自己抛) / `tool-fail` / `tool-slow` /
   `tool-clash`(自家工具与外部撞名) / `server-down` / `server-start-broke`(第三方起不来) /
   `config-broke`(配置读不动); 另有**三条不是故障**: `ping`(扩展探活, 喂 `env-up.sh`
   "扩展最后探活"那条判据) / `tools-capped`(一张表里装不下的工具被砍, 见 ADR-0003) /
   `result-capped`(结果超预算被砍, 见 ADR-0003). 扩展侧是**环节**: `health`(周期探活) /
   `call`(工具调用) / `watchdog`(看门狗停手) / `rounds`(8 轮到顶) / `continuation`(续聊那一
   跳). 这半句**有守卫**: 联合类型(`src/lib/failurelog.ts` 的 `FailureWhere`)与它两头对拍 --
   加了环节不补篇, 或者篇里点着一个仓里没有的名字, 都会红. 增删要**三处**一起动: 这张表, `tests/test_log.py` 里那份册子, 以及调用点 -- 三处都在
   测试的射程里(册子 ↔ 调用点, 册子 ↔ 这张表; 少动一处就红).
5. **悬停只在绿着时摆历史**: 当前红着时第一句就是原因, 重复一遍只是噪音.
6. **续聊失败要能说清断在哪一步**: 环节 `continuation`, 每个失败点一条稳定的原因短句
   (`src/lib/continuationfail.ts`) -- 尤其"没找到输入框""输入框写不进去""Enter 与发送键都没
   发出去"**三种不合并**, 它们修法不同. 上报走既有的 MAIN → 隔离 → background 通道.
   图标状态机, 角标, 对话流一律不因此改变.
7. **现场帧**: 只抓**发送类**失败, 且只在真的落了**新**记录的那一刻抓(同一次红着的延续不重复
   拍; `watchdog` / `rounds` / 健康探活不抓 -- 它们的现场在中继与图标上, 不在标签页).
8. **不抢前台**: 只在报上来的那个标签页此刻仍是**窗口的活动标签页**时抓; 后台页, 或者活动页
   已经换人, 一律跳过, 留纯文字因由. `captureVisibleTab` 拍的是窗口的活动标签页, 不校验就会
   把别的站点拍下来存进库.
9. **帧与痕拼在一起, 不新增上报面**: 独立键 `ds-/failure-frames`, 按 `at` 与失败记录配对,
   帧随记录一起过期, 滚动保留最近 5 帧. 只进本地 `storage.local`, **没有任何出站路径**.
10. **体积有界**: 整屏 JPEG 先按质量 70 抓, 超 55k 字符预算就用 `OffscreenCanvas` 逐步降采样
    重编码; 压不进预算就**丢帧留文字** -- 宁可不拍, 不让一帧把 10MB 的配额啃掉一块.
11. **让人眼看**: 选项页"上次故障"那一行下面摆这一帧的缩略, **只在帧与最前面那笔记录配得上
    时**显示(配不上就不显示 -- 宁可没有, 不能张冠李戴).
12. **抓帧绝不影响原失败路径**: 全链路 fire-and-forget, 任何一步(权限, 超时, 配额, 编码,
    标签页没了)失败都静默降级回纯文字; 原失败路径的语义一行不改. 抓帧失败不留印(失败痕记的
    是**故障**, 不是"抓帧这件事"有没有成).
13. **不加成本开关**: 失败本身就是罕见事件, 抓帧只在失败那一瞬发生; 再加开关等于给"故障时要人
    先去开"埋雷. 可见的瞬间闪烁随失败一起出现, 接受.
14. **权限: `host_permissions` 收成 `<all_urls>`**. `captureVisibleTab` 的硬要求是
    `<all_urls>` 或 `activeTab`, **站点级 host 权限不算数**(实机证伪:
    `Either the '<all_urls>' or 'activeTab' permission is required.`). `activeTab` 要人点一下
    图标才授, 与"失败当场自动抓"不相容. **内容脚本的注入范围不动**(仍钉在
    `chat.deepseek.com`); 中继仍走 host 直连免 CORS(ADR-0002).

## Considered Options

- **只打浏览器控制台**(原状): DevTools 不是常开的, SW 重启即清; 而且超时 / 连不上 / 非 2xx
  会被折成同一件, 连"为什么"都没留下. 否决.
- **中继自己写日志文件**: 多一个路径, 轮转, 权限的配置面. stderr 已经能被
  `nohup pnpm relay:dev > /tmp/dsb-relay.log 2>&1` 收下. 否决.
- **把失败摆进对话流或弹个提示**: 违房规 -- 失败提示只在扩展侧, 进度与失败都不进对话流. 否决.
- **连正文一起记**: 违房规, 而且没有诊断价值(要看的是**为什么**失败). 否决.
- **给续聊失败翻红图标**: 会把"结果没送到模型手上"与"中继没连上"并成同一个信号, 误导排查
  方向, 而且红着的时候恰恰没有别的信息可看. 否决.
- **只记一个"续聊失败"不带原因**: 答不出断在哪一步, 等于把控制台那一行搬了个地方. 否决.
- **在选项页加一块失败痕列表**: 新增 UI, 可见信号已经有(悬停), 重复造一个只会两处不同步.
  否决.
- **续聊失败绕开去重, 各记一笔**: 几秒就能把 20 条配额刷满. 否决.
- **不抓帧, 只存结构化现场**(可见性 / composer 字数 / 圆键相 / 横幅文本 / 行数): 零权限,
  不碰正文, 但它答不了"页面**看着**什么样"(布局崩没崩, 横幅长什么样), 而真机上那些问题恰恰是
  从"图上看一眼就明白"的. 留作退路, 今天不走.
- **`activeTab` + 人点图标才抓**: 抓帧变成手动动作 -- 失败得人当场点一下, 且现场得还在屏上.
  否决.
- **`chrome.debugger` + `Page.captureScreenshot`**: 不用 `<all_urls>`, 但要加 `debugger`
  权限, 每次抓都亮一条"正在调试此浏览器"横幅, 还跟用户自己的 DevTools 抢连接. 否决.
- **把帧塞进失败记录同一条**: 读取器只挑已知字段, 帧会被原样丢掉; 而且帧大记录小, 过期纪律也
  不同源. 否决.
- **抓完把对话区裁掉 / 打码**: 权限问题一模一样, 而且裁到哪儿才不碰正文说不清. 否决.

## Consequences

- **装了 `<all_urls>`**: 扩展在技术上能拍任何标签页. 功能上只用一处 -- 失败那一瞬报上来的
  那个标签页, 且它必须还是活动页. 这是明确认下的代价(与"站点范围钉死"那条旧口径冲突, 以本条
  为准).
- **"不记正文"多一处显式例外**: 帧里是页面像素, 可能就是用户的对话. 边界是本地, 有界(5 帧 +
  单帧预算), 随记录过期, **没有任何出站路径**. 要上传或以别的方式外发, 那是另一次决策.
- **帧的读取器与失败痕同一条纪律**: `storage.local` 是外部输入, 长得不对的一条条丢掉, 不猜
  也不补.
- **同一次故障的延续不重复拍**: 帧的条数因此落后于痕的条数, 这是有意的 -- 现场是"那一刻",
  不是"每一刻".

## 判据(怎么自己复现)

```sh
pnpm vitest run src/lib/failureframe.test.ts src/lib/continuationfail.test.ts
uv run scripts/page-action.py visible-capture     # 抓不抓得到
uv run scripts/page-action.py frame-fail          # 抓不到时不影响原失败路径
uv run pytest tests/test_log.py -q                # 事件名册子 ↔ 调用点 ↔ 篇里那张表
uv run scripts/page-action.py storage get --keys '["ds-/failure-frames"]'   # 帧落没落, 多大(开发期)

# 红: 把某个调用点的事件名打错一个字母(dsb/gateway.py 的 server-down → server-dow),
# 那条"调用点对着册子核"当场红(11 条里 1 条); 只改 tests/test_log.py 里那份册子而不动篇,
# 册子那两条一起红(同一次量到 2 条).
```

`frame-fail` 那条负路的真机读数(痕照落, 帧没多, 跑完原样)与两个探针坑见
`docs/evidence/failures-and-frames.md`.
