# 续聊走请求体替换:可见的只剩一个短标记,轮数有上限

- **Status**: accepted
- **Date**: 2026-10-04
- **Supersedes**: none

一次工具调用原来就是一条 `agent:` 开头的**长用户消息**(TOON 正文全文进对话历史),
一轮一条,而且这条消息是扩展自己发的.账号在站点那边是**阶梯处罚**过的(3 天判到 8 天),
"发了几条"不是唯一判据,但它是唯一能自己压住的行为面--把结果的正文从"可见消息"挪到
"出站请求体",会话里就只剩两行标记.

做法抄参考项目 WebTool-DeepSeek(把 MCP 装进网页版 AI 的那条线走得更早):短标记进输入框,
真正给模型的正文由 main world 在出站请求体里替换(`core/interceptor/fetch-hook.ts` 的
`pendingContinuationPrompt`),外加 `MAX_CONTINUATION_ROUNDS = 8` 的轮数上限与
`detail.slice(0, 2000)` 的结果截断.

## 决定

1. **正文改走请求体**:`inject.ts` 的 `recognizeOutgoingShape` 认出出站形状,
   它给出的 `replacePending` 把那一趟出站的
   `prompt`(或 `messages` 里最后一条 user)换成 `buildContinuation` 组出来的正文;对话里
   发的是 `CONTINUATION_MARKER`(`agent:` 锚 + 一行"继续").模型侧的读法**一字未改**
   --仍是首行锚 + TOON 载荷,所以协议说明只加了一句.
2. **轮数有上限**:`MAX_CONTINUATION_ROUNDS = 8`(`src/lib/rounds.ts`).到顶就停手
   --这一轮不发,计数归零,报给 background 记一笔(失败留痕的新环节
   `rounds`/"续聊刹车"),等用户开口再继续.答复里没有围栏就算任务收尾,轮数归零.
3. **结果截断**:`MAX_RESULT_CHARS = 2000`,截断处写明"已截断"与原长--让模型知道
   它看到的不是全文,会据此改问法,而不是拿半截正文当全貌.
4. **武装时机**:续聊正文在**出站窗口放行那一刻**才武装(入队到开窗有几秒,期间用户可能
   自己在发消息),且**一次即作废**--替换没成也作废:宁可少一轮,也不能把用户的真消息
   当成续聊那趟,正文被工具结果顶掉.

## Considered Options

- **照旧回灌长消息**:一轮一条 TOON 全文,历史里全是机器痕迹,每条还都是扩展自己发的
  --风控面上最贵的就是这个,否决.
- **只把文案改短,不动请求体**:机器痕迹照样留在历史里,也没碰到"量的来源",否决.
- **把截断放到中继**:中继只交结构化结果,编码与呈现归扩展(ADR-0011 的口径);
  截断是"给模型看多少",属扩展侧,否决.
- **轮数上限做成可配**:先写死 8(与参考项目同值),要调再加 `storage` 覆写.

## Consequences

- 一条任务里可见的用户消息从"一轮一条 TOON 全文"降到"一轮一个两行标记";工具结果
  只在模型那儿,不进可见流.
- **站点改发消息的形状,替换就落空**:那一轮作废(控制台留一行"没能替换进去"),
  不猜,也不退回长消息.
- `wait.reply` 等到的现在是那条短标记而不是载荷正文--名册里的等动作口径随之变小.
- 看门狗的静默催办(15 分钟)与这里的刹车是两套闸:刹车停的是"扩展自动往下续",催办是
  "长时间没动静就替用户说一句'继续'",后者仍受"代你发言"闸拦.
- "结果没送到模型手上"与"中继没连上"是两件事:前者只在控制台看得见,后者照旧不进
  对话流,图标翻红.

## 补记:答复要认 id(2026-10-17,#108)

上面第 1 条只管**发出去**的那一趟;"回来"的那一趟原先没有归属判据,于是留了一条同形的岔路.

页面世界排一圈围栏(`call` 信封,带 `id`),隔离世界跑完把答复投回来(`result` 信封,
同一个 `id`).收信那一侧**不看 id**:谁的 `result` 进来都当"这一轮的工具结果回来了"
排进续聊.探针 `scripts/page-action.py` 正是用同一条链驱动本地工具的--它投一条
`{"tool":"send.page",...}`(id 形如 `probe-send-page-...`),在信封上与一轮真围栏一模一样,
答复也一模一样地回来.于是**每跑一次 `send-page`,续聊就多拿到一个"工具结果",凭空多发
一条 `agent:继续`**,而且那条的正文是探针的答复,不是真工具结果.

12:56:03 那笔 `send-failed` 就是这么来的:模型正在答上一条真 `继续`,这条撞上去,Enter
与圆键都发不出去(抓到的帧上:模型正在生成).同一处对话里还留着更早的现场:两圈围栏
之间,对话留下了**三条** `agent:继续`,其中一条前面没有围栏.

判据收在 `src/lib/fencecalls.ts`:排 `call` 时记下 id,收 `result` 时**只认自己排出去,
还没收过的那一个**,别的丢掉并在控制台留一行(信封上有 id,不必猜).一轮一次--重放与
重投一并挡住;名单 FIFO 有界(16 个),漏掉的答复挤掉最老的.探针不受影响:它驱动工具走
的是隔离世界那条路,判据读的是页面状态(`landed` / `composerAfter` / 账本),不靠这一跳.

**真机复验(2026-10-17,闸开着)**:环境先按 `scripts/env-up.sh` 换成本仓当时那版(构建比
源码旧,跑之前是旧扩展),再用 `send-page --send` 连跑三轮**带真围栏**的问题--模型各发了
一次 `read`.三轮都是:围栏一条,`agent:继续` **恰好一条**,没有凭空多出来的那一条;账本
20 笔痕 / 3 帧三轮没动.修之前正是**探针自己的** `send.page` 答复多喂进一轮(探针每跑一次
就多一条 `agent:继续`),这条现在也验掉了:同一次复验里探针的答复不再被当成工具结果.
后两轮的正文成了 ADR-0026 / ADR-0027 的读页证据(单行标注, 翻页脚注, 整页 13,492 字).

顺带一件事:那笔 12:56:03 的 `send-failed` 头痕在这两轮之后**已恢复**(`recoveredAt` 落上,
头不再红)--旧扩展里那一下是模型正答上一条真 `继续` 时被挤进来的,新代码没再发生.
