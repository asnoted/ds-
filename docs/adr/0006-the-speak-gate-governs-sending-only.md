# ADR-0006: "代你发言"闸只管发送; 闸关着时自动续聊变半自动

- **Status**: accepted
- **Date**: 2026-10-17

`speak` 闸(选项页的复选框, 默认关)管的是"**是否允许替你把消息发出去**":
受闸的是所有发送 -- `send.enter`, 发送态的圆键, `message.retry`, 看门狗催办的发送, 自动续聊
的发送. 往输入框里写字(`composer.type` / `composer.clear`)**出闸** -- 往输入框里写字不叫
替人开口. 闸关着不是停摆, 是**只落草稿**: 自动续聊把短标记写进输入框, 等用户自己按发送.

改这一条的原因: 闸原先管"动写作框的"动作, 而自动续聊在 MAIN 世界直接操作 DOM, 不经
`runAction`, 也拿不到 `speak` 键 -- 于是用户关掉闸之后, 催办停了, `send.page` 停了, 但
**切换照跑**, 工具结果每轮回来仍往账号里塞一条真实用户消息. 从选项页看到的因果是"我关了
'替我说话', 它确实不催我了", 合理推断是这条闸管着所有代替我发言的行为 -- 实际不是.

## 决定

1. **闸的语义 = "是否允许替你把消息发出去"**. 受闸的是所有发送; `composer.type` /
   `composer.clear` 出闸.
2. **`speak` 跨世界**. 隔离世界每次广播开关状态时一并带上, MAIN 世界按它决定自动发还是只
   落草稿; 选项页勾选**即时生效**(改 `storage` → 立刻再广播, 不必刷新页面).
   **缺字段的旧信封按"关"处理**(保守: 宁可等用户按).
3. **闸关着时自动续聊变半自动**: 不按 Enter, 不点发送键, 只把短标记写进输入框, 等用户自己按
   发送. 用户随后发出的那条, 正文逐字等于标记 → 被换成工具结果(钥匙, ADR-0005).
4. **待发续聊没有期限**: 钥匙使时间不再是安全判据, "等多久都安全". 它是**单槽**, 新一轮顶掉
   旧的. 失效条件只有五条: 被消费, 被新一轮顶掉, 换了页面会话, 总开关关掉, 用户发出了别的
   话(钥匙不符).
5. **输入框里有你的草稿就不覆盖**: 这一轮作废, 留一笔失败痕(`draft-in-composer`). 与"宁可
   少一轮, 也不能吃人说的话"同源.
6. **看门狗催办在闸关着时整个跳过**(不写, 不发) -- 它是"写 + 发"成对的动作, 只写不发会在你
   的输入框里留下半截"继续". 跳过即不算催, 计数不动.
7. **`send.page` 写步放行, 发送步被拦**, 回现有的 `disabled`(**不新增失败码**), 那条问题
   留在输入框当草稿. 原来的两步步序照走, 行为自然落成这个.
8. **写输入框不再受闸, 意味着协调者能覆盖你正在打的草稿**. 这是明确接受的取舍, **选项页文案
   如实写明**(原先那句"不会碰你正在打的东西"不再成立, 已删). 本条**不加**覆盖保护(续聊那条
   路径除外, 见第 5 条).
9. **选项页加一行"上次故障"**: 读既有的失败痕(ADR-0008), **不新增任何上报**. 8 轮到顶
   (环节 `rounds`)与续聊那一跳的各种失败(环节 `continuation`)都能在那里看见, 不必翻控制台.
10. **`composer.type` / `composer.clear` 仍在退避闸下**: 它们是写动作, 账号在处罚区时照拦.
    原先它们是靠"在 `speak` 名单里"顺带进的退避闸, 语义换了以后必须**显式**列进
    `BACKOFF_GATED_ACTIONS`, 否则会跟着漏.

## Considered Options

- **维持原状(续聊不受闸), 只在选项页补一句文案**: 用户仍然可能在不知情的情况下被塞消息.
  选项页那一句谁会读? 而"代你发言"这个名字就在复选框上. 否决.
- **`speak` 关着就停续聊**: 总开关单独开着会**什么都干不了**, 两个开关实际合并成一个,
  "接管页面"与"替人开口"的分工就没了. 半自动是更细的粒度: 接管照旧, 只把最后一步交给人.
  否决.
- **半自动下让协调者仍然自动按发送, 只是不写长正文**: 那还是替人发言, 闸形同虚设. 否决.
- **半自动时把短标记换成一句更明显的话**: 会把 TOON 载荷的痕迹摆进可见流, 与"可见的只剩
  两行"相悖. 否决.
- **把待发续聊也设一个 TTL**: 钥匙落地后时间不是安全判据, 设不设都不影响安全性, 只会在用户
  没立刻按的时候白作废一轮. 否决.
- **闸关着时往输入框写"续聊中..."之类的提示占位**: 占位本身就是替人写输入框, 还要多一套
  清理逻辑. 否决.

## Consequences

- **默认体验**: `speak` 默认关, 所以**默认情况下自动续聊是半自动的** -- 总开关 = 是否接管
  页面(续聊的授权), `speak` = 能否替你发出, 退避 = 账号在处罚区时暂缓写动作, 三者各自独立.
- **`SPEAK_GATED_ACTIONS` 与 `BACKOFF_GATED_ACTIONS` 不再互为子集**: 两张名单都要显式维护,
  新增动作要分别想清楚.
- **选项页不再承诺"不会碰你正在打的东西"**: 想恢复那个保证需要另加覆盖保护(不在本条).
- **失败痕多一个可见处**: 选项页的"上次故障"与图标悬停读同一份记录(ADR-0008), 两处同源.

## 判据(怎么自己复现)

```sh
pnpm vitest run src/lib/gate.test.ts src/lib/run.test.ts src/lib/registry.test.ts
uv run pytest tests/test_probe_send_page.py -q

# 红: 把 src/lib/armed.ts 的 planContinuation 改成一律 `{ action: "arm-and-send" }`(闸关了

# 行上的 `speak` 翻成 false, registry.test.ts 那条"发送原语都受闸"当场红 -- 那条是 2026-10-18
# 补的: 补之前翻这个标志谁都拦不住(闸名单是从标志派生的, 自洽照旧).
```

真机那几半(闸关着时写作框压着 `agent:\n继续` 不动 / 闸开着时没人按它也自己续完 /
闸关着时看门狗催办整跳跳过且不计数 / 闸关着时 `send.page` 只落草稿)见
`docs/evidence/speak-gate.md`; 后两半的跑法与逐条读数(不给 `--send` 的
`send-page`, 看门狗探针默认腿), 以及 `composer.type` 顶掉草稿的观感, 都在那份文件的
"真机验证(2026-10-18)"节.
