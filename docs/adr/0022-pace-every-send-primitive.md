# ADR-0022: 发送原语全局限速:三条发送路合成一条 3~5 秒的线

- **Status**: accepted
- **Date**: 2026-10-08
- **Supersedes**: none

本篇把 ADR-0002 的出站保护窗口**从"自动续聊这一路"扩到"所有替用户发出去的消息"**,
补上它原先没管的两条路.ADR-0002 与 ADR-0014 **不因此改动**--出站口本身,续聊刹车,
回灌机制都没动.

## 问题

出站窗口(ADR-0002)原先只管**自动续聊**:内容排进队列,开窗放行,两次之间必隔
3~5 秒.另两条发送路走 `runAction`,压根不经过它:

- **看门狗催办**:15 分钟没动静就替用户说一句"继续";
- **`send.page`**:本地工具,往页面发一条问题.

于是站点那边看到的是"一次 `send.page` 和一次续聊可能在一秒内连发"--同一账号,
短时间,多条用户消息,正是阶梯处罚盯上的行为面.扩展侧对这件事**没有可压住的把手**:
各路各自限速,加起来仍可能连发.

## 决定

1. **三种"替用户把消息发出去"的原语**统一受一条限速:两次触发之间必隔 3~5 秒随机,
   **沿用 `outbound.ts` 的 `WINDOW_MIN_MS` / `WINDOW_MAX_MS`**(与出站窗口同一区间),
   但**不共用状态**--这里记的是"最近一次发送时刻",与队列放行语义不同,各记各的.
2. **等,不拒**:间隔不够就**等**够,绝不拒绝,绝不新增失败码(#61 原票口径).
   调用方等完照发,agent 侧看不出差别.
3. **"停止"永不延迟**.圆键那一下可能是发送,也可能是中断生成(真机 2026-10-05:
   class 一个不换,只有图标 `d` 换).判出 `stop` 就不等;**判不出也不等**--宁可少限
   一次速,也不能延迟一次中断.
4. **记发送比限速更保守**:判不出意图的圆键点击照样记一笔"可能发出去了".宁可之后
   多等一次,也不漏记一次发送.
5. **跨世界靠既有的 `window.postMessage` 通报时刻**,不迁状态,不写 DOM 属性.通报带
   `world` 字段,**两边都不认自己发的**(`postMessage` 也投递给发送方自己).并的是
   **较晚**的那个时刻,间隔各抽各的--覆盖会把更早那次丢掉,紧接着的第二下就少等.
6. **续聊队列,轮数刹车不动**:出站口与 8 轮刹车是**另一层**闸,本篇在它之外再加一条
   跨路线的限制,两者都在.
7. **本票不承诺能避免禁言**.阶梯处罚的判据是站点侧的行为面,3~5 秒只是把"机器节奏"
   压到人也能做到的量级;账号仍可能进处罚区,退避闸(`backoff.ts`)照旧照着处置.

## Considered Options

- **让另两条路也排进出站口队列**(`gate.ts`):真正统一的一条路,但要跨世界重构--队列
  与窗口状态在 MAIN 世界,另两条在隔离世界,中间得过 background.改动面大得多,而本
  要的只是"别连发"这一条性质.否决.
- **只在 background 侧限速**(那里能看到每一次动作):MAIN 世界的续聊发送它看不见,照样
  能与一次 `send.page` 连发.否决.
- **间隔不够就拒绝**(回 `disabled`):给动作集加一个失败码,agent 侧要处理新的错误
  分支,而用户与 agent 都没做错什么--只是发得急一点.**等**比**拒**更贴近真实语义.
  否决.
- **把圆键点击一律限速**(不判意图):会把"停止"也延迟--那是在延长一次用户明确要的
  中断.否决.
- **把限速做成用户可配**:默认值已经明确,可配只多一个配置面与一套测试.否决(本票).

## Consequences

- **`send.enter`,圆键(发送态),`message.retry`,自动续聊的发送**现在共享一条线.
  一次 `send.page` 之后立刻续聊,续聊会等满剩下的间隔.
- **看门狗催办也可能被等**(它是发送).催办本就在静默期(15 分钟无动静)触发,实际
  撞上间隔的概率极低.
- **跨世界多一条 `send-note` 消息**(`window.postMessage`,各自世界认各自的),不落
  `storage`,不上 background--限速是当页行为,刷新后重新计时即可.
- **检查点是一个入口,两种世界的两份实现**(`content.ts` 的 `paceRoster` 与
  `inject.content.ts` 的 `paceSend`),都走 `sendpace.ts` 同一个 `checkSendIntent`.
  #52 要往里加"拒绝"这一种结论(`speak` 闸关着就不许发),届时不必改这三个字段的含义.
- **旧 ADR 一字未改**:ADR-0002 的"出站窗口"仍只管续聊这一路;本篇是它**之外**的一层.
