# ADR-0010: 工作工具的结果有界而且给得出下一步: 翻页, 整条闸, 墙钟

- **Status**: accepted
- **Date**: 2026-10-17

自家五件工作工具交出的东西必须**有界**, 而且**看得懂下一步**:

- `read` **按行翻页**: 正文逐行带 `行号: ` 前缀, 末尾一句脚注说读到哪与接着读什么;
- `ls` / `grep` **一整条有闸**: 超了砍在**行边界**上, 末行写明怎么续;
- `grep` 整趟躺在 20 秒**墙钟**里, 过线整个中止;
- 所有这些额度都**连末尾那句一起算** -- 一页连着脚注, 一条结果连着末句.

这条的目的写在最前面: 一次读大文件, 模型原先**看不到其余 87%, 而且没有任何办法看到**
(dsb 交出 16,000 字, 回灌只给 2,000 字, 翻页能力没有). 截断那句文案也帮不上忙 --
`...(已截断, 超出 14464 字符)`: 模型只知道"少了", 不知道少了哪些, 在哪, 怎么接着看.

## 决定

### `read`: 按行翻页

1. **`offset` 是 1-based 起始行号**(默认 1), **`limit` 是读多少行**(默认 200, 最多 2000).
   按行不按字符: 模型想的是行, `grep` 也是行向的; 按字符会让 `offset` 落在一行中间.
2. **三态脚注, 各自说清读到哪**:

   ```
   1: ...
   2: ...
   (第 121-200 行 / 共 843 行,接着读:offset=201)          <- 页到头, 文件还有
   (字节预算截断,第 1-200 行 / 共 843 行,接着读:offset=201)  <- 预算砍在半路
   (文件读完:共 843 行)                                   <- 读完, 不编下一步
   ```

   **只有真有下一读的那种才给 `offset=`** -- "读完"那句不给, 不然模型会去读一个不存在的
   第 844 行.

3. **四个上限各管一件事**: 单页默认 `WORK_READ_PAGE_LINES = 200`, 单页上限
   `WORK_READ_MAX_LINES = 2000`, 单行 `WORK_READ_LINE_LIMIT = 500` 字, 单次
   `WORK_READ_BYTES = 16_000`. **单行超限另标**(`...(本行超 500 字)`) -- 静默截断会让模型
   以为那就是整行.
4. **预算小到一行都放不下时仍然给那一行**(哪怕超预算): 空页对模型最没用 -- 它拿不到任何
   内容, 连翻到哪都不知道.
5. **`offset` 越界回 `bad-range`**; **`limit` 超上限按上限给**, 不报错(模型把 99999 写进来也
   能拿到一页).
6. **`splitlines` 的口径**: 先 `removesuffix("\n")` 再切 -- 以换行结尾的文件不多算一行, 中间
   空行照旧算行, 空文件回"共 0 行". 总数错就是模型眼里的文件错(它拿那个数判断"读完了没有").
7. **"逐字"改成它真正保证的那句**: `read` 的保真口径是**不丢, 不猜, 不改写内容**;
   **行号是呈现层的前缀, 正文内容一字未改**. 带行号之后它不再是逐字的, 但实质能力没有放松.

### `ls` / `grep`: 一整条有闸

8. **同一道闸 `cap_result(text, hint)`**, 数值 `WORK_RESULT_CHARS = 16_000`, 与一页 `read`
   **同数**(一条结果 = 一页): 一个数比两个数好记, 两个数同源由一条测试钉住.
9. **砍在行边界上**: 半行比没有更坏(模型会把半行当成一整行, 与 `render_page` 标单行的理由
   同一条).
10. **末行说清下一步**, 由调用方给一句 `hint` -- 闸只知道"太大了", 不知道"怎么变小":

    - `ls`: `...(整条超 16000 字,已截断:给了前 78 行 / 共 500 行;换个更小的目录再列)`
    - `grep`: `...;收窄模式,或指定 path 分几次搜)`

11. **`read` / `write` / `edit` 不加这道闸**: `read` 那条路由页预算兜住, 后两件回执是一行.
    给 `read` 套上只会在它真咬的那一次**把脚注砍掉**, 而脚注是 `offset` 的唯一来源.
12. **不学网关那句"已截断:原文 N 字"**(模型拿着那句什么都做不了); `cap_result` 这个名字与
    网关那个同名, 但文案与切法不同, 两边各自读得懂.

### `grep`: 墙钟

13. **整趟(编译 + 遍历 + 逐行匹配)躺在 `WORK_GREP_DEADLINE = 20.0` 的墙钟里**, 过线抛
    `pattern-too-slow`, 正文写"模式 ... 未在 20s 内搜完(换简单点的写法, 或指定 path 缩小
    范围)". **整个中止, 不给半份结果** -- 半份结果会被当成"就这些命中".
14. **装闸的手法**: `signal.setitimer` 加上一个抛 `WorkError` 的处理函数, 进出各一次
    (`dsb/work.py` 的 `_deadline`). **装不上就不装**(`signal` 只能在主线程装, Windows 没有
    `setitimer`): 这道闸是兜底, 不是语义的一部分.
15. **不换 ripgrep**: 线性时间是它最硬的理由, 而这条理由用十几行标准库就买到了; 换它要付的是
    二进制分发(npm 那个平台包 Python 侧拿不到)与方言收窄.
16. **方言写进工具描述**: 描述与 `pattern` 参数都写明"Python `re` 语法"; "模式太费会中止"
    这句也写上 -- 模型得知道它会被中止, 才会去改写.

### 额度连末尾那句一起算

17. **两个闸都按"最终交出去的那一整条不超过额度"来花**:
    `render_page` 每收一行先预留"这一行的换行 + 1 + 这一页脚注的**最长写法**";
    `cap_result` 先算末句的保守长度(行号位数按最大取), 再按"行 + 末句 <= 额度"砍.
18. **贴边时少给一行, 而不是多给一句**: 给不下的那行按 `offset` 下一次给, 而脚注里正写着它.
19. **判据是两边共用的一条**: 扩展那句"工具结果已截断"在自家工作工具这条路上**一次都不该
    出现** -- dsb 交出的每一条结果 `<= 16_000`.
20. **"字"是 UTF-16 单元, 不是码点**(`dsb/work.py` 的 `_units()`): 那道闸长在扩展侧, 而
    JS 的 `.length` 数的是 UTF-16 单元(星平面字算两个). dsb 原先用 Python 的 `len()`(码点)
    -- 纯 CJK 与 ASCII 下两个数相等, 所以从没露过; 正文里出现星平面字(emoji 之类)时同一个
    串在扩展侧量出来更大, 第 19 条在那里破口. 同一个串两边必须量出同一个数, 这条有 fixture
    钉着: `protocol/fixtures/result-units.json`, TS 与 pytest 各自量一遍(谁也不引用谁).
21. **失败回执与成功正文过同一道闸**: `_wrap` / `_bad_path` 拼出来的 `code(detail)` 也走
    `cap_result`(hint 是"把参数改短或改窄再试"). `detail` 里回显的是模型自己写进来的串
    (模式 / 路径), 一行就能几十万字 -- 不过闸那一趟底下只剩 JSON-RPC 的
    `MAX_BODY_BYTES = 256 * 1024` 兜着. 于是 `cap_result` 的契约是**任何正文进来, 出门的
    那一整条都不超额度**: 行边界砍不下整行时(第一行自己就超)在行内砍, 末句说清被砍在哪.

## Considered Options

- **只放宽回灌上限, 不加翻页**: 模型能看到更多, 但一次仍只能看开头 -- 16,000 字之后的依然
  永远看不到. 否决.
- **按字符翻页**: `offset` 落在一行中间, 行向的思考用不上. 否决.
- **不带行号, 只补位置与翻页**: 保住"逐字"字面, 代价是模型看不到行内位置 -- 而"不丢不猜不改
  内容"这条实质, 行号并不违反. 否决.
- **做 tail / 头尾混合**(给日志用): 范围外. 否决.
- **`limit` 越界报错**: 模型写个 99999 就整轮作废, 而给上限它照样拿到一页. 否决.
- **若定案成 48000 / 32000 / 8000**: 48000 那档测得最漂亮(模型主动 `grep` 定位, 只读 20 行,
  三个答案全对), 但"预算给宽是安全的"不等于"该给宽"; 32000 没崩不等于该用; 8000 或更小没有
  证据支撑, 只会多几次翻页(每次翻页都是一轮). 三条都是**为不存在的问题付代价**. 否决.
- **按 DSH 的 2000 行取用**: 那是它自己仓里的默认, 不是我们的答案. 实测 200 行够用. 否决.
- **把上界无限抬高**(比如与网关的 64K 对齐): 等于取消这道闸, 而实测证明预算这一维本来就不
  构成约束 -- 留着一个不常咬人的闸不如留着它. 否决.
- **不管模型读多了**: 读全文不算错, 它自己判断"要确认没遗漏"; 48000 档证明它**不总是读多**,
  所以这不是需要治的行为. 否决(当缺陷处理).
- **自家五件全走网关的 `cap_result`**: 那道的文案是"结果已截断: 原文 N 字", 且从头部整条砍
  -- 套到 `read` 上会把脚注砍掉. 否决.
- **每个出口各写一份截断文案**: 形状一样的两处各写一份, 必漂. 采纳它的**精神**(末行给下一
  步), 但做成一道共享闸加一句 `hint`.
- **照 dsh 的 spill 办**(超了落文件, 内联给一页加取用提示): 形状对, 但**落点与保留期是产品
  决定**, 而且我们的 `read` 本来就能按 `offset` 取 -- 落第二份存储面等于多一个要盘的东西.
  留作重议的退路.
- **只给 `grep` 加闸**: `ls` 一样能到一个十万字, 两处同形, 分别加必漂. 否决.
- **不设闸, 靠扩展那道 16,000**: 它截的时候内存与 storage 已经被灌过一遍, 而且它不知道这一段
  是文件列表还是命中, 截出来的东西说不出"该怎么续". 否决.
- **在子进程里跑 `grep` 再 `join(deadline)`**: 一样能断, 但要为一件纯函数引入进程边界(结果
  回传, 孩子不许污染 stdout 上那条 JSON-RPC). 能被信号打断就不必. 否决.
- **只给单行配预算**: 逐行装表要每行两次系统调用, 而且"这一行超了就跳过"改掉了 `grep` 的
  语义. 否决.
- **限制模式语法**(禁嵌套量词): 要写一个正则的小解析器, 判不准就漏, 判错就误伤. 否决.
- **让 gateway 在 `tool-timeout` 时杀掉并重启孩子**: 那是更一般的那道网, 但它救的是**整台
  中继**而不是这一次调用, 模型要等满 120s 才拿到一个没头没尾的 `tool-timeout`. 已由
  ADR-0003 补上; `grep` 自己这道墙钟留着(它早得多, 准得多, 还给得出能照着改的码).
- **把扩展那道 16,000 抬高一点**(多留一行加一句): 两个数就**不同数**了, "一页原样进对话"
  那条承诺要跟着改, 而且抬高多少都得跟着单行上限走. 否决.
- **只在扩展侧留头留尾, 截中间**: 脚注能活, 但模型拿到的是**拼接过的正文**, 而且 dsb 交出的
  东西仍然比它自己声明的大. 否决.
- **把页预算写小一点**(比如 15,000)留余量: 那是**把余量写死成数**, 与"两个数同数"直接冲突,
  而且没人知道该留多少(要留的是换行 + 脚注, 随行数变). 否决.

## Consequences

- **模型看大文件不再停在 12%**: 一页 16,000 字原样进对话, 而且**它知道接着读什么**.
- **`read` 的输出形状变了**: 三处测试从"逐字等于文件内容"改成"逐字等于带行号的那页"
  (`test_work.py` / `test_work_permissions.py` / `test_mcp_server.py`); 它们钉的是**新契约**.
- **最坏情况有界**: `ls` / `grep` 一条结果 `<= 16,000` 字(实测 101,999 -> 15,961,
  102,311 -> 15,890).
- **`README.md` 的"限额与超时"多一行**(工作工具一条结果), 并接进
  `tests/test_readme_limits.py` 的 `ROWS`: 数从 `dsb/work.py` 重算, 对不上就红.
- **`protocol/fixtures/read.json` 是两半共读的判据**(`readPageLines` / `readPageBudget`),
  vitest 对着同一份断言.
- **总成本由文件决定, 档只决定分几轮**: 同一份 25,679 字的文件, 三档的合计几乎一样
  (29,321~29,397 字), 差的那部分主要是行号与脚注的开销.
- **探针多了一个 `focus` 动作**(`Page.bringToFront`): 读页面列表前必须先来一下, 否则
  `messages.*` 恒空(后台标签页虚拟列表不挂行) -- 这是测出"第三道墙是测试环境自己"的副产品.
- **重议的触发条件**: 真机反复出现"收窄也拿不到要看的东西"(比如只有一条正则收得动, 而前 80
  条命中都不是要的那条), 那就该走 dsh 那条路 -- 整份落文件加取用提示.

## 判据(怎么自己复现)

```sh
# 翻页 / 单行标注 / 整条闸 / 末句留位 / 两边的"字"同一把尺 / 失败回执也过闸
uv run pytest tests/test_work.py tests/test_mcp_server.py -q \
  -k 'whole_result or one_result or one_read_page or last_line or overlong_line or utf16 or huge_detail or astral'

# 墙钟: 闸跟着走(纯函数层 + 工具载荷层)
uv run pytest tests/test_work.py -q -k 'backtracking or blew_up'

# 不误伤: 本仓上最慢的那档(实测 3.5s)照常出命中
uv run scripts/measure-result-forms.py grep --pattern 'ERROR_' --json

# 量法(两条闸都看 _units(...) 与末行)
#   render_page(["x" * 100] * 400, 1, 200)  /  cap_result(...)
```

三档实测(每轮多少字), 那个真 bug(脚注总数多算一行), 单行标注与翻页脚注到模型手里的真机
读数, 见 `docs/evidence/read-pages.md`; `ls` / `grep` 那两个十万字的坏数字与修法见
`docs/evidence/work-result-caps.md`.

## 未验证项

- ~~**`limit = 2000` 那个上限在真实内容上"够不够"**: 一个默认页(200 行)就几 KB, 字节预算先咬,
  所以它在真机上轮不到 -- 边界只在代码侧验过(要 9999 行回**恰好** 2000 行并给 `offset=2001`).~~
  -- **已量(2026-10-18)**: 默认工作根里 2000 行以上的真文件有 18 个(最长 13835 行); 拿最长
  那份读, `limit=2000` 那一页在第 262 行就被**字节预算**截断(15987 字, 脚注给了下一个
  `offset`) -- 上限够, 但真内容上轮不到它. 顺带量到默认那一页不是"几 KB": 行长的文件里
  200 行就到 13629 字(16K 里剩 2.4K). 读数见 `docs/evidence/work-result-caps.md`.
- ~~**20.0 这个数是从一个仓库量的**: 更慢的机器, 更大的仓(或网络盘)上会不会误伤, 没量.~~ --
  **已量(2026-10-18)**: 换两棵更大的树走完整遍(`node_modules` 155M / 9706 个文件 = 2.59s;
  `/opt/homebrew` = 7.01s), 都没撞墙; 宽模式先咬的是结果闸(0.04s 就回了). 于是误伤那一头
  的门槛大致是"比这台机器慢三倍以上, 又走这么大的一棵树"; 读数与推算见
  `docs/evidence/work-result-caps.md`. **网络盘仍没量**(本机没这条件).
- **模型拿到 `pattern-too-slow` 之后会不会照着重写**: 没验.
- **多线程里装不上**: 目前活工具都在子进程主线程里跑, 所以生效; 哪天挪进线程池, 这道闸会
  静悄悄退化成"不装", 那时要另想办法.
- ~~**正文本身以"数字 + 冒号"开头的文件**: 模型会不会把行号前缀与正文混起来, 没验~~ --
  **已验(2026-10-18 07:45)**: 真机上一份五行文件, 第 3 行正文自己以 123: 开头, 第 4 行以
  45: 67: 开头; 让模型照抄, 它把前缀与正文分得清(报成 3: 123: ... 与 4: 45: 67: ...),
  还自己先说了一句"行号是 read 工具给的前缀, 后面是原文". 读数与走查见
  `docs/evidence/read-pages.md` 的"真机验证(2026-10-18)"节. 两位数与三位数行号此前已验
  (n=2), 这一条 n=1.
