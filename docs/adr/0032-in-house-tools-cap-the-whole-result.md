# ADR-0032: 自家工作工具补上"整条结果"的闸:`ls`/`grep` 按整行砍,末行写明怎么续

- **Status**: accepted
- **Date**: 2026-10-17
- **Supersedes**: none

**只修订 ADR-0027 的一点**:它把"自家五件工具没有内存/存储闸"记成已知缺口,并明确
"**本篇不拍这个板**".本篇拍这个板.ADR-0026/0027 的形状与数值**一个字不改**
(`WORK_READ_PAGE_LINES = 200` 与 `WORK_READ_BYTES = 16_000` 仍是定案值).

## 问题

ADR-0027 的勘误段查到两件事:`cap_result` 全仓只有一处调用(`gateway.py`,第三方 MCP
server 的结果那条路),而**自家五件工具经 `mcp.py` 的 `text_result` 直接出门,只封装
不截断**.它当时担心的对象是 `read`,并给了两条补法(自家也走 `cap_result`,或让自家那道
截断文案认得翻页).

这回按那两条补法处置之前,先量了一遍"到底哪件没有闸".答案是**不是 `read`**.

## 摸清的事实(数字都是本轮实测)

1. **`read` 那条路本来就有闸**:`render_page` 逐行累加到 `WORK_READ_BYTES`(16_000)就断,
   断在半路时脚注先说"字节预算截断"再给 `offset=`;单行另有 `WORK_READ_LINE_LIMIT`(500)
   这道.**任何配置下**这条路的整条结果都被页预算兜住:最多比预算多一行(预算小到放不下
   时那一行仍然给它)加一句脚注.(2026-10-17 补:换行与脚注从此也算进那笔预算,于是"兜住"
   从"预算 + 同行加脚注"收紧成**就是预算本身**,见
   [ADR-0035](./0035-the-budget-includes-the-closing-line.md).)
2. **`ls` 没闸**:`WORK_LIST_LIMIT = 500` 只管件数,名字长度没人管.500 个各 200 字名字的
   目录项,一条结果实测 **101,999 字**.
3. **`grep` 没闸**:`WORK_GREP_LIMIT = 200` 件 x `WORK_LINE_LIMIT = 500` 字,每维都没超,
   合起来实测 **102,311 字**.
4. 这两个十万字的东西**一路都是真的**:进中继的内存,进扩展 storage,再进对话.网关那道
   64K 只管第三方 server 那条路;扩展那道 16,000 字是**回灌进对话时**才截的,截的时候东西
   已经造出来,也已经传过一趟了.
5. 所以 ADR-0027 那句"`read` 没有总量闸"**指错了件**:真正裸着的是"列"与"搜"这两件--
   它们的输出是**一列不定长的行**,而行长与件数各有一道上限,恰好谁都不管总和.

## 两条参考实现(不用它们的代码,用它们的形状)

- **pi**(`packages/coding-agent/src/core/tools/truncate.ts`):一个**共享**的截断闸,两个
  独立上限(默认 2000 行 / 50KB)**谁先到谁赢**,并**永不返回半行**;每个工具自己写
  "接着怎么办"的提示(`grep` 那句是 `Use limit=400 for more, or refine pattern`).
- **dsh**(`packages/fs/`):`read` 把上限做成显式 caps(一次 `limit` / 单行 `maxLineLength` /
  一次 `maxBytes`),结果里带 `truncatedByBytes` 标记,好让上层知道"是字节截的不是行截的";
  搜索那条路另配 **spill**--超了把整份结果落文件,内联只给一页加一句
  `Full sorted result stored at: <locator>. <retrievalHint>`.

## 决定

**给"列"与"搜"两件加上同一道总量闸:`cap_result(text, hint)`(`dsb/work.py`).**

1. 数值 `WORK_RESULT_CHARS = 16_000`,与 `read` 的一页**同数**(一条结果 = 一页):一个数
   比两个数好记,而且 16,000 正是 ADR-0027 实测验过,模型一页用得动的档.两个数同源由
   一条测试钉住.
2. **砍在行边界上**:半行比没有更坏(模型会把半行当成一整行,与 `render_page` 标单行
   同一条理由).
3. **末行说清下一步**,由调用方给一句 `hint`--闸只知道"太大了",不知道"怎么变小":
   - `ls`:`...(整条超 16000 字,已截断:给了前 78 行 / 共 500 行;换个更小的目录再列)`
   - `grep`:`...;收窄模式,或指定 path 分几次搜)`
4. **`read` / `write` / `edit` 不加**:前者那条路的闸就是页预算(事实 1),后两件回执是
   一行.给 `read` 套上只会在它真咬的那一次**把脚注砍掉**,而脚注是 `offset` 的唯一来源.
5. **不学网关那句"已截断:原文 N 字"**(ADR-0027 原话:模型拿着那句什么都做不了).
   `cap_result` 这个名字与网关那个同名,但**文案与切法不同**,两边各自读得懂.

## Considered Options

- **自家五件全走网关的 `cap_result`**(ADR-0027 补法一):那道的文案是"结果已截断:原文 N 字,
  这里是前 N 字",且从头部整条砍--同一道闸套到 `read` 上会把脚注砍掉.否决.
- **每个出口各写一份截断文案**(补法二的字面读法):形状一样的两处各写一份,必漂.采纳它
  的**精神**(末行给下一步),但做成一道共享闸加一句 `hint`.否决字面做法.
- **照 dsh 的 spill 办**(超了落文件,内联给一页加取用提示):形状对,但**落点与保留期是
  产品决定**(dsh 自己有一整套 spill-policy / retention),而且我们的 `read` 本来就能按
  `offset` 取--落第二份存储面等于多一个要盘的东西.留作重议的退路(见 Consequences).否决.
- **只给 `grep` 加**:`ls` 一样能到一个十万字(101,999),两处同形,分别加必漂.否决.
- **不设闸,靠扩展那道 16,000 字**:它截的时候内存与 storage 已经被灌过一遍,而且它不知道
  这一段是文件列表还是命中,截出来的东西说不出"该怎么续".否决.
- **给 `read` 也套同一道**:见决定第 4 条--唯一会咬到的场合,正是它最需要脚注的场合.否决.

## Consequences

- **最坏情况有界了**:`ls` / `grep` 一条结果 <= 16,000 字(实测 101,999 -> 15,961,
  102,311 -> 15,890).(2026-10-17 补:末句从此也算额度,这个界在贴边的形状下才真的守得住,
  见 [ADR-0035](./0035-the-budget-includes-the-closing-line.md).)
- **README"限额与超时"多一行**(工作工具一条结果),并**接进 `tests/test_readme_limits.py`
  的 `ROWS`**:数从 `dsb/work.py` 重算,落点点常量名,对不上就红(加行没接线也红).
- **四条测试钉住**:两件各一条(连末行文案一起钉)+ `read` 一页的界 + "两个数同源".
- **行为面的代价**:命中很多时模型看到的是前几十条,要自己收窄--提示就写在末行.这是有意
  的:它本来也不该把 200 条各 500 字全塞进对话.
- **重议的触发条件**:真机反复出现"收窄也拿不到要看的东西"(比如只有一条正则收得动,而
  前 80 条命中都不是要的那条),那就该走 dsh 那条路--整份落文件加取用提示.

## 判据(怎么自己复现)

- **四条测试**:`uv run pytest tests/test_work.py -q -k "caps_the_whole_result or one_result or one_read_page"`.
- **那两个坏数字怎么量出来的**:把 `WORK_RESULT_CHARS` 调到很大(等于撤掉这道闸)再调一次
  `list_dir` / `grep_tree`,看结果字数;测试里就是 monkeypatch 这个常量把闸压小,连末行
  文案一起钉.
- **参考实现**:`vendor/pi-mono`(截断闸)与 `vendor/deepseek-harness`(caps 与 spill)是按
  `AGENTS.md` 的口径落在 `vendor/`(本机装出来的东西,不进库)的浅克隆
  (`--depth 1 --filter=blob:none --sparse`,只取看的那几个目录);只用来看形状.
