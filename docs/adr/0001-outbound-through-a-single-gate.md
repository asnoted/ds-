# ADR-0001: 唯一出站口,每会话聊天双方共享一条 3~15 秒的限速队列

- **Status**: accepted — 历史文档: 所描述的 Python 中继 + 浏览器扩展在 3d0c51a 已删除, 现行实现是 dsweb/lib 与 dsb/lib 两个 DSH 插件
- **Date**: 2026-10-17

网页模型和拓展每一条消息都要过一个队列,队列中每条消息必隔一个 **Beta(2,4) 的 3~15 秒随机间隔**(峰在 6 秒, 两端密度趋于零)

## 决定

1. **唯一出站口管的是回灌路**: 每一条消息排进队列,发送需求只在队列排空时允许, 不能绕开.
   **诚实边界**: 只挡`send.page`
2. **间隔取 Beta(2,4)**
   **采样用次序统计量, 不靠拒绝抽样**: 5 个均匀数里第 2 小的那个恰好服从 Beta(2,4)
   (第 k 个次序统计量 ~ Beta(k, n+1−k); k=2, n=5), 天然有界, 恰好五次 `random()`, 没有循环.
3. **所有发送原语合成一条线**: `send.enter`, 发送态的圆键, `message.retry`, 看门狗催办的
4. **全仓唯一一条限速**

## Considered Options

- **逐条发送 + 固定间隔**: 实测已证伪, 间隔合规照样撞限流. 否决.
- **让另两条路也排进出站口队列**: 真正统一的一条路, 但队列与窗口状态在 MAIN 世界, 另两条在
  隔离世界, 中间得过 background; 要的只是"别连发"这一条性质. 否决.
- **只在 background 侧限速**: MAIN 世界的续聊发送它看不见, 照样能与一次 `send.page` 连发.
  否决.
- **间隔不够就拒绝**(回 `disabled`): 给动作集加一个失败码, agent 侧要处理新的错误分支,
  而用户与 agent 都没做错什么 -- 只是发得急一点. 否决.
- **把圆键点击一律限速**(不判意图): 会把"停止"也延迟, 那是在延长一次用户明确要的中断. 否决.
- **用截断/夹取的 Beta 采样**(拒绝抽样或反函数 + 夹取): 夹取会在两个端点堆出概率尖刺,
  正好违背"两端趋于零". 否决.
- **把限速做成用户可配**: 默认值已经明确, 可配只多一个配置面与一套测试. 否决.
- **三态状态机(正常 / 长休 / 退避)**: 现在由退避闸独立承担, 不混进这道口.

## Consequences

- **单来回下队列恒只有一个元素**; 多块一轮(ADR-0002)时, 用户插话与在途回灌的顺序仍按队列
  先来后到.
- **一次 `send.page` 之后立刻续聊**, 续聊会等满剩下的间隔; 看门狗催办本就在静默期
  (15 分钟无动静)触发, 实际撞上间隔的概率极低.
- **跨世界多一条 `send-note` 消息**, 不落 `storage`, 不上 background -- 限速是当页行为,
  刷新后重新计时即可.
- **发送等待的最坏情形是 15 秒**(旧分布是 5 秒): 排探针与真机验收的时序余量按新上界算.
- **站点是否对单条消息长度另有判据**未实测; 合并后的消息更长, 这一条仍开着(见
  `docs/evidence/outbound-and-mutes.md`).
