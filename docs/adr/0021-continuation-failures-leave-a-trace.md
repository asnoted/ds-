# ADR-0021: 续聊失败留痕:新增 `continuation` 环节,可见信号是悬停那一句

- **Status**: accepted
- **Date**: 2026-10-07
- **Supersedes**: none

本篇**细化 ADR-0004 的环节清单**(新增 `continuation`),并把 ADR-0014 Consequences 里
那条"结果没送到模型手上只在控制台看得见"落成留痕.ADR-0004 与 ADR-0014 **不因此改动**.

## 问题

自动续聊的每一跳失败都只有一行 `console.log`,不翻红,不进扩展存储.于是扩展侧**没有任何
地方**能回答"为什么这一轮工具结果没回到模型手上".从外面看三者都像正常:页面里没有新
助手消息(用户以为站点卡住了),模型没拿到工具结果(它以为工具挂了,可能重试),**图标
一片绿**.

这也是 #47 那类问题(`send.page` 坏着,还重复发消息)难以被发现的原因--真机跑一遍页面像
是好的,只有翻控制台才知道第三步断了.

## 决定

1. **新增失败环节 `continuation`**(`FailureWhere` 的第六项),悬停里显示为"续聊".
   `isFailureWhere` 判据与 `WHERE_LABELS` 标签表同步加(这三处必须逐字对齐).
2. **每个失败点一条稳定的原因短句**(`continuationfail.ts`),彼此能区分--尤其
   "没找到输入框""输入框写不进去""Enter 与发送键都没发出去"**三种不合并**,它们
   修法不同.册子外的码照原样带上,不丢成空白.
3. **沿用既有的 MAIN → 隔离 → background 上报通道**(ask / stop 走的就是它),由
   background 落痕.这些失败点都在 MAIN 世界,那里写不了 `storage.local`.
4. **正文进不来**(ADR-0004):短句由常量给出,调用点写不出问题,答复,工具结果或用户
   消息.`sendToPage` 抛错时**只留错误类型名**,不带 message--message 里可能嵌着用户
   正在打的东西.
5. **图标状态机,角标,对话流一律不变.** 可见信号就是悬停里那一句--图标绿着时回看
   "上次故障 ... / 续聊 / 没找到输入框".这正是 `watchdog` 环节现在用的可见信号,
   所以本票**不新增任何 UI**.
6. **同一次故障只记一笔**的既有去重与 20 条配额**照旧适用**,续聊不开后门;同一个失败
   点不重复上报.

## Considered Options

- **给续聊失败翻红图标**:把"结果没送到模型手上"与"中继没连上"并成同一个信号.
  后者有可恢复的探活,前者是一次性的动作失败(下一轮照样能跑),翻红会误导排查方向,
  而且红着的时候恰恰没有别的信息可看.否决.
- **把失败写进对话流或弹提示**:违房规--失败提示只在扩展侧,进度与失败都不进对话流.
- **只记一个"续聊失败"不带原因**:答不出断在哪一步,等于把控制台那一行搬了个地方.
  仍然答不出问题.
- **在选项页加一块失败痕列表**:新增 UI,不在本票必要范围内;可见信号已经有(悬停),
  重复造一个只会两处不同步.
- **续聊失败绕开去重,各记一笔**:探活每 30s,续聊每轮都可能失败,几秒就能把 20 条配额
  刷满,真正要看的前因后果被冲掉.否决.

## Consequences

- **失败痕多一个环节**.图标标题那句现在可能是"上次故障 ... / 续聊 / 输入框写不进去".
  旧记录里的 `health` / `call` / `watchdog` / `rounds` 一律照旧读得出来.
- **多了一条上报消息**(`continuation-fail` kind / `ds-/continuation-fail` type),遵守
  "三路消息各有唯一构造与解析点"与"跨边界载荷一律过 parse"的既有口径.
- **失败即留痕,行为不变**:本票只记录,不重试,不自动恢复,不改任何发送或替换行为.
- **本机工具(`send.page` 等)的失败口径不动**--它们有调用方拿错误码,仍只进控制台.
- **真机可验**:在未登录 / 禁言的页面触发一次续聊,悬停里应出现"续聊 / 没找到输入框".
  验不了就在 PR 里标**未验证**.
