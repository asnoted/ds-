# ADR-0024: dsb 工作工具的权限规则层:规则是数据,按操作分档

- **Status**: accepted
- **Date**: 2026-10-08
- **Supersedes**: none

本篇**只修订 ADR-0012 的一点**(它否决的"读写分档 / 敏感名单"),其余不动.ADR-0012
**不因此改动**.

## 问题

ADR-0012 给五件工作工具(`ls` / `read` / `grep` / `write` / `edit`)定了两条护栏:路径
`resolve()` 后必须落在 root 内(`out-of-root`),**写/改额外拒 `.git/`**.分诊核实实现时
发现两个缺口,都因为**默认 root 是仓根**,而仓根里恰好住着两个不该让模型碰的本机配置:

- **`mcp.json`**:dsb 启动时用 `subprocess.Popen` 直接拉起其中的 `command` + `args`.
  模型 `write` 它,**下次中继重启就是任意命令执行**(它被 gitignore,`git diff` 看不到
  改动).它的 `env` 里还可能放着第三方 MCP 服务的 API key,`read` / `grep` 读出来会
  **随回灌进对话,也就是发给站点**.ADR-0012 声称的"无命令执行面"由此有一条间接通路.
- **`.env`**:可以改 `DSB_WORK_ROOT`.模型把 root 改成 `~`,下次重启沙箱就被它自己撑开.

## 决定

**规则是数据,不是代码里的名单.** 照 opencode 的权限口径(`opencode.ai/docs/permissions`)
做一张声明式规则表:按操作分类(`read` = 读内容,`edit` = 写/改),每条
`pattern → allow | deny`,通配符 `*`(零个或多个任意字符,**含 `/`**)与 `?`(恰好一个
字符),**最后一条命中的规则赢**,通常先写兜底 `*` 再写更具体的.

**只认 `allow` / `deny`**:dsb 是被动的无状态网关(ADR-0011),没有交互面,
opencode 的逐次确认(`ask`)无处安放.

匹配对象是**根相对,POSIX 分隔,`resolve()` 之后**的路径--符号链接与 `..` 因此绕不过去.
**匹配大小写不敏感**:macOS 文件系统默认大小写不敏感而 `resolve()` **不规范化大小写**,
`MCP.JSON` 能打开真文件却会躲过字符串匹配(这是实现期发现的坑,不是设计时就想到的).

**默认表**(`dsb/permissions.py`):

| 操作   | 拒                                           |
| ------ | -------------------------------------------- |
| `read` | `*.env`,`*.env.*`,`mcp.json`                 |
| `edit` | `.git`,`.git/*`,`*.env`,`*.env.*`,`mcp.json` |

`.env.example` 显式放行(它是给人看的模板,里面没有真密钥).`.git/` 从"写死的特例"收进
这张表--`.git/hooks` 与 `mcp.json` 是同一类文件(不经人看就会执行),护栏的理由本来就
一样.既有 `.git` 行为要求**逐项等价**,`tests/test_work.py` 一字未改全过.

**第二层:保护真实生效的那两个文件.** 规则表比的是**名字**;`mcp.json` 可以被
`DSB_MCP_CONFIG` 指到 root 内别处,`.env` 可以被 `find_dotenv()` 挪到当前目录.所以除了
规则表,还按**实际路径**拦 dsb 真正会读的那两个文件(复用配置模块已有的解析,不在工作
工具里重新猜路径).落在 root 内就读写都拒,不在 root 内由 `out-of-root` 管.

**`grep` 对每个文件套读规则**,命中 deny 就跳过--结果里不能出现那些文件的任何内容,哪怕
模式正好命中里面的某行.**`ls` 仍如实列出名字**(只拦内容,不隐藏存在,与 opencode 一致).

**本票不做用户可配**(没有配置面,YAGNI),但表是易扩展的数据结构,不写在各工具的 `if` 里.

## Considered Options

- **继续在代码里加两个 `if`**:改动最小,但下次有人要加第三个文件,就是第三次在各个工具
  里插判断--而 `grep` 的遍历,`read`,`write`,`edit` 四处都要记得插.否决.
- **把整个 root 之外的路径都拒**(换个更小的 root):那要用户自己配目录,而默认 root 是仓
  根这个既有事实不变;`DSB_WORK_ROOT` 恰恰是可以被改的(见上面 `.env` 那条).否决.
- **`.env` 只拒不跨目录的精确名**(`.env` 而非 `*.env`):各处子目录下的 `.env` 同样是
  真密钥来源,漏一个就是漏.跨目录的 `*` 正是 opencode 的口径.采纳.
- **按绝对路径拦而不是根相对**:模型能传绝对路径(`resolve_in_root` 接受),按绝对路径
  写规则表就没法写.根相对 + `resolve()` 之后,既统一又挡得住符号链接.采纳.
- **只拦写不拦读**(照旧 `.git` 的做法):`mcp.json` 的 `env` 里可能有 API key,读出来
  **随回灌发给站点**--读侧漏了这条,比写侧漏了更隐蔽.opencode 默认也拒读 `.env`.否决.
- **做成真正的沙箱**(白名单目录树,限制编辑范围):那是另一个量级的工程,且 ADR-0012
  已经把"全部动作钉死在一个工作文件夹 root 内"定为边界.本篇是在那条边界内补一层规则,
  不是把边界换掉.否决.

## Consequences

- **两套错码分工不变**:`out-of-root`(越出 root)与 `protected-path`(root 内但受保护),
  `protected-path` 的语义从"只写不读"扩成"读或写都受保护".**没有新增错码**.
- **`grep` 会跳过比从前更多的文件**(`mcp.json` / `.env` 系,以及它们的符号链接).
  `ls` 不受影响--文件名照旧列出来.
- **根相对路径是判定的唯一依据**,所以规则表里写的东西都是人可读的名字;真实路径那层
  (`mcp.json` 被配置指到别处)不在表里表达,避免表退化成一张散乱的名字名单.
- **规则表是数据**:将来加一条保护是往 `DEFAULT_RULES` 里加一个 `Rule`,不是改控制流.
- **既有 `.git` 行为等价**:`protected_git` 现在是 `is_protected(..., "edit")` 的薄壳,
  `tests/test_work.py` 的 60 条**一字未改**全过.
- **真机可验**:在临时 root 里放一个带标记串的假 `mcp.json`,用 MCP 入口调 `read` /
  `grep` / `write`,确认读不到标记串,也写不进去.已在测试里用真文件做过一轮
  (`tests/test_work_permissions.py`,含符号链接与大小写两组绕过).
- 旧 ADR 一字未改:ADR-0012 写的仍是无命令执行面与 root 边界,本篇是它**之内**的一层.
