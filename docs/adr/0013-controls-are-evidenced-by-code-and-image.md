# ADR-0013: 制作最小单元必须原样保留按钮的代码与图片

- **Status**: accepted
- **Date**: 2026-10-17

**最小单元** = 页面动作名册按控件划出的最小粒度(一个按钮只能对应一个动作). 登记一个最小单元
时, 除了动作名, 定位与返回形状, 还得**原样留下那个按钮的代码与图片**, 而且**由测试检查它们
符合原样**.

为什么: 真机爬下来的答案是**有些按钮除了图, 没有任何东西能认出它是谁**. 消息工具栏一排 6 颗
按钮**逐字节同形**: `div[role=button]` + `ds-button ds-button--iconLabelTertiary ds-button--icon
ds-button--capsule ds-button--xs ds-button--icon-relative-l` + 同一个哈希 `db183363`,
`tabindex=0`. 其中只有第 5 颗带 `aria-label="朗读"`, 第 2 颗带 `aria-disabled=false`(那是
状态, 不是身份); **剩下 4 颗 -- 复制 / 喜欢 / 不喜欢 / 分享 -- 同类, 同哈希, 无文字, 无
`title`, 无 `data-*`, 无 `aria-label`, 完全无从分辨**. 它们的身份是逐颗**悬停 tooltip** 才读
出来的, 而 tooltip 只在真机悬停时出现, jsdom 里等不到.

两条既有规矩框住这件事: "控件定位优先设计系统语义锚"明令**图标 `path` 不作定位判据**;
"真机 DOM 落成回归用例"要求抓到的真实 `outerHTML` 原样进 jsdom 用例. 于是留下一个真空:
**能认出身份的(图)不能当判据, 能当判据的(`ds-*` / `role` / `aria-*`)认不出身份** --
身份必须单独留档, 否则最小单元做完就再也指不回那颗按钮.

## 决定

1. **按钮的代码**: 真机抓到的 `outerHTML` 一段 -- tag, 全部 class(**含哈希 class**), `role`,
   `aria-*`, `tabindex`, `style`, 内部结构, **一个字不缩写**; 连同它所在的**那一排**:
   父容器, 同排几颗, 它排第几, 从哪颗语义锚(如 `[aria-label="朗读"]`)数起.
2. **按钮的图片**: 它的图 -- 内联 `svg` 的 `viewBox` 与全部 `path` 原文(`fill` / `stroke`
   一并留); `svg` 拿不到时截一张图存下.
3. **测试时必须检查"是否符合原样"**, 不许只把规矩写下来靠自觉. 比对的对象是**真机原件**,
   链上两处逐字比, 缺一处缩写就从缝里进去:
   - **站点 → 留档原件**(真机对账): 探针把留档的 `outerHTML` 与站点当前那一颗逐字比, 不等就
     报"站点改版, 存证过时", 让人重抓. 这一半要真机, 要登录, 要 paced 探针, **CI 够不着**,
     故按需本地跑, 不塞进 `pnpm quality`.
   - **留档原件 → 回归用例里用的那份**(CI 对拍): 进 `pnpm quality`, 改一边就红. 用例里
     **不许手抄**原件: 原件住文件, 用例从文件读(或与文件逐字对拍), 让"缩写"没有落脚点.
4. **落点**:
   - **已实现的最小单元** → 照抄真机的 jsdom 回归用例(注释标**真机日期**);
   - **只登记, 还没实现的候补** → 按同样要求先存下(代码 + 图 + 真机日期), 实现时原样搬进回归
     用例; **不许先写一句文字描述占位**.
5. **边界(与决定一起写死)**: 代码与图片是**证据**, 不是**定位判据**. 定位仍按"控件定位优先
   设计系统语义锚"走(`ds-*` / `role` / `aria-*`), 图标 `path` 照旧不作判据 -- 留图是为了对账
   与找回, 不是为了拿它当选择器.

## Considered Options

- **只写文字描述**(现状的一部分): 同形按钮文字分不开(4 颗逐字节一样), 描述还会随人改写而漂,
  且没有任何一处能被回归用例钉住. 否决.
- **把图标 `path` 当定位判据**: 与"控件定位优先设计系统语义锚"直接冲突, 站点换一次图标就失效;
  按图标分家会让两条路对同一元素给出矛盾判断. 否决.
- **整页截图代替按钮级存证**: 截图没有结构, 指不出是哪一颗; 按钮级的图才对得上账(可以与代码
  并存, 但不能替代代码). 否决.
- **只写文字规矩, 不加测试**: 规矩**早就在**("真机 DOM 落成回归用例"), 而缩写的 fixture 还是
  发生了: **没有测试的规矩拦不住任何人**, "原样"靠自觉最不可靠. 否决.

## Consequences

- **Good: 同形按钮找得回** -- 既不依赖真机悬停 tooltip, 也不依赖随时会变的哈希 class.
- **Good: 站点改版时有账可对**: 新的 `outerHTML` 与存证并排一比就知道哪颗变了, 变成什么样;
  回归用例(既有规矩)先红.
- **Good: 与"图标不作定位判据"不冲突** -- 证据与判据是两件事, 边界写死在决定里.
- **Bad: 真机对账那半进不了 CI**(要登录 + paced 探针), "符合原样"的**最强证据不是每次提交都
  有**; CI 那半只保证"没人手抄改写", 证不了"站上还是这样".
- **Bad: 登记变重**. 每颗按钮要贴完整 `outerHTML`(含 `svg path`, 一颗几百字), 候补那批十几颗
  下来体积可观; 存证**会过时**, 必须靠真机日期区分"当时"与"现在".
- **Bad: 存量要回补** -- `messages.test.ts` 的代码块 fixture 是缩写过的, 按本条该补回原样;
  补的时候要确认 `readRow` 对真实结构仍成立(那是实现要认的结构, 不能只改测试).
