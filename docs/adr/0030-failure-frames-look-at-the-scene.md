# ADR-0030: 失败当场留一帧:零现场问题不再靠猜,代价是 `<all_urls>` 与 ADR-0004 的一处例外

- **Status**: accepted
- **Date**: 2026-10-16
- **Supersedes**: none

本篇**给 ADR-0004 开一处显式的例外**(帧里是页面像素,也就可能是用户的对话内容),
并**改动 manifest 的那条"站点范围钉死"**--原来只有 `chat.deepseek.com` 与中继的
`127.0.0.1/localhost` 那几条,现在收成 `<all_urls>`.ADR-0004 的其余部分**不因此改动**.

## 问题

#104 收尾后,真机反复被"零现场"卡住:失败痕(ADR-0004)只有**时刻 / 环节 / 原因短句**,
"Enter 与发送键都没发出去"发生的那一刻,页面到底长什么样--composer 里是不是还留着半截
草稿,站点有没有挂横幅,圆键停在哪个相,对话区挂没挂行--**全靠猜**,归因只能试错.

探针侧有 `page-action.py read` 那点结构化读数,但它读的是**现在**,回不到**失败那一刻**的那一屏;
而失败是异步报上来的,等人在页面上看见,现场往往已经被站点重挂掉了.

## 决定

1. **只抓发送类失败,且只在真的落了新记录时抓**.触发点收在 background 的 `continuation`
   上报处(带 `sender.tab`):`recordFailure("continuation", ...)` 真写出一条**新**记录的那一刻
   才抓一帧(靠返回值判定).同一次红着的延续不重复拍;watchdog / rounds / 健康探活不抓--
   它们的现场在中继与图标上,不在标签页.
2. **不抢前台**.只在报上来的那个标签页此刻仍是**窗口的活动标签页**时抓;后台页,或者活动页
   已经换人,一律跳过,留纯文字因由.`captureVisibleTab` 拍的是窗口的活动标签页,不校验就会
   把**别的站点**拍下来存进库--那既拍错对象,又抓了不相干的内容.
3. **帧与痕拼在一起,不新增上报面**.独立键 `ds-/failure-frames`,按 `at` 与失败记录配对,
   帧随记录一起过期(记录滚出册子的帧清掉),滚动保留最近 5 帧.只进本地 `storage.local`,
   **没有任何出站路径**.分键存是因为 `readFailureLog` 只挑它认识的字段,塞进同一条会被丢.
4. **体积有界**.整屏 JPEG 先按质量 70 抓,超 55k 字符预算就用 `OffscreenCanvas` 逐步降采样
   重编码;压不进预算就**丢帧留文字**--宁可不拍,不让一帧把 10MB 的配额啃掉一块.
5. **让人眼看** .选项页"上次故障"那一行下面摆这一帧的缩略,**只在帧与最前面那笔记录配对
   得上时**显示(配不上就不显示--宁可没有,不能张冠李戴).开发期照旧读 storage.
6. **抓帧绝不影响原失败路径**.全链路 fire-and-forget,任何一步(权限,超时,配额,编码,
   标签页没了)失败都静默降级回纯文字;原失败路径的语义一行不改.
7. **不加成本开关**.失败本身就是罕见事件,抓帧只在失败那一瞬发生;再加开关等于给
   "故障时要人先去开"埋雷.可见的瞬间闪烁随失败一起出现,接受.
8. **权限:host_permissions 收成 `<all_urls>`**.`captureVisibleTab` 的硬要求是
   `<all_urls>` 或 `activeTab`,**站点级 host 权限不算数**--此前票里"扩展对
   `chat.deepseek.com` 有 host 权限所以能用"是个没验过的前提,实机证伪:
   `Either the '<all_urls>' or 'activeTab' permission is required.`
   (判据:`uv run scripts/page-action.py visible-capture`).`activeTab` 要人点一下图标才授,
   与"失败当场自动抓"不相容.**内容脚本的注入范围不动**(仍钉在 `chat.deepseek.com`,
   见各 entrypoint 的 `matches`);中继仍走 host 直连免 CORS(ADR-0011).

## Considered Options

- **不抓帧,只存结构化现场**(可见性 / composer 字数 / 圆键相 / 横幅文本 / 行数):零权限,
  不碰正文,但它答不了"页面**看着**什么样"(布局崩没崩,横幅长什么样),而票里那些问题
  恰恰是从"图上看一眼就明白"的.留作退路,今天不走.
- **`activeTab` + 人点图标才抓**:不扩权限,但抓帧变成手动动作--失败得人当场点一下,且现场
  得还在屏上.自动"当场抓"这条不成立,否决.
- **`chrome.debugger` + `Page.captureScreenshot`**:不用 `<all_urls>`,但要加 `debugger`
  权限,每次抓都亮一条"正在调试此浏览器"横幅,还跟用户自己的 DevTools 抢连接.否决.
- **把帧塞进失败记录同一条**:读取器只挑已知字段,帧会被原样丢掉;而且帧大记录小,
  过期纪律也不同源.否决.
- **抓完把对话区裁掉 / 打码**:权限问题一模一样(还是要 `captureVisibleTab`),而且裁到哪儿
  才不碰正文说不清.否决.
- **沿用"探针手动截图"**:它抓的是**人来看的那一刻**,不是失败那一刻;真机那几次失败正是
  "事后去看已经看不出来"的情形.

## Consequences

- **装了 `<all_urls>`**:扩展在技术上能拍任何标签页.功能上只用一处--失败那一瞬的报上来的
  那个标签页,且它必须还是活动页.这是产品面拍过板认下的代价(与"站点范围钉死"那条旧口径
  冲突,以本篇为准).
- **ADR-0004 的"不记正文"多一处例外**:帧里是页面像素,可能就是用户的对话.边界是
  本地,有界(5 帧 + 单帧预算),随记录过期,**没有任何出站路径**.要上传或以别的方式
  外发,那是另一次决策.
- **真机口径**:`uv run scripts/page-action.py visible-capture` 验"抓不抓得到";
  `uv run scripts/page-action.py frame-fail` 验"抓不到时**不影响原失败路径**"(把站点退后台,
  投一笔失败:痕照落,帧数没变;决定 6 那条红线);
  `storage get --keys '["ds-/failure-frames"]'` 验帧落没落,多大.
- **抓帧失败不留印**:它不进失败痕,也不进图标--失败痕记的是**故障**,不是**抓帧这件事**
  有没有成.排查抓帧本身要看 background 控制台.
- **帧的读取器与失败痕同一条纪律**:`storage.local` 是外部输入,长得不对的一条条丢掉,
  不猜也不补.

## 真机验证(2026-10-17):抓帧失败那条负路

`uv run scripts/page-action.py frame-fail` 连着两趟都回 `ok: true`:

```json
{
  "toggleOn": true,
  "failuresBefore": 19,
  "framesBefore": 0,
  "activeWhileReporting": "chrome-extension://.../options.html",
  "injected": "sent",
  "recorded": true,
  "framesAfter": 0,
  "restored": true,
  "failuresAfter": 19,
  "ok": true
}
```

- **痕照落**:19 到 20(最前面那笔 `{where:"continuation", cause:"探针造的失败:验抓帧负路(#106)"}`),
  而 `activeWhileReporting` 是选项页--站点标签页当时**不在前台**,抓帧那一步走不通.
- **帧没多**:仍是 0.抓帧失败对原失败路径一个字没影响(决定 6 那条红线的真机证据).
- **跑完原样**:探针造的那笔痕撤掉(它只是一次验证;留在册子里会一直挂在选项页的
  "上次故障"上--真探活只在由红转绿那一下补恢复时刻),`failuresAfter` 回到 19.
  两趟连着都绿,说明这道判据可重复.

**顺手记一个坑**:background 手里那份留痕是**内存副本**,只在总开关键变时才从
`storage.local` 重读(`syncFromStorage`).所以"直接往 storage 写一笔假痕"这种做法,
改的只是 storage,内存那份没动;而 `rememberFailure` 的口径是"最前面那笔还没恢复就
不新起一条",于是**下一笔真痕再也落不下来**,探针会一直报 `recorded: false`,而错的
是探针.`frame-fail` 因此跑完扳一下总开关(关,再开)让两边对齐--这一步住在探针里,
不写进产品:产品手里那份本来就该跟着开关走.
