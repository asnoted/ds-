# ADR-0004: 所有出站经唯一出站口, 发送原语共享一条 3~15 秒的线

- **Status**: accepted
- **Date**: 2026-10-17

扩展往页面发的每一条**自动续聊**消息都要过同一个出站口(`src/lib/gate.ts`), 窗口开启时
一次性发出. 所有"替用户把消息发出去"的原语之间必隔一个 **Beta(2,4) 的 3~15 秒随机间隔**
(峰在 6 秒, 两端密度趋于零): `WINDOW_MIN_MS = 3000`, `WINDOW_MAX_MS = 15000`,
`WINDOW_MODE_MS = 6000`(`src/lib/outbound.ts`).

依据是 2026-09-26/28 的实测: 一轮 7 次工具执行产生 6 条回灌, **每条间隔都合规**
(3.8s / 5.0s / 3.7s / 3.4s / 2.3s / 15.4s), 末尾仍然撞上 `finish_reason: rate_limit_reached`,
模型的收尾回答被整个吃掉, 随后账号被禁言 3 天. 结论: **节流合规不等于不会被限流, 减少消息
条数本身是独立的必要措施** -- 真正的单位是"发了几条", 不是"隔了多久".

**这道闸不承诺避开禁言**: 出站口落地之后账号仍被禁言, 刑期从 3 天加到 8 天. 站点判的是什么
没搞清(登录/会话/并发/内容特征都可能在里头, 条数顶多是必要条件之一). 那道账归退避闸
(`src/lib/backoff.ts`)与"账号处境"(ADR-0007), 不记在这道口上.

## 决定

1. **唯一出站口管的是自动续聊这一路**: 续聊的每一条消息排进队列, 窗口开启时一次性发出
   (含首条 -- 入队那一次也要等满). 新增发送需求只能排进队列, 不能绕开.
   **诚实边界**: "唯一"只对续聊成立; 看门狗催办(`deliverNudge`)与本地工具 `send.page`
   走 `runAction` → `page.ts` 的 `writeComposer` + `pressEnter`, 不经 `gate.ts`.
   它们由下面第 4 条那条线覆盖, 不假装被出站口管着. 要不要把它们也排进出站口队列, 是另一次
   决定(跨世界重构, 收益与风险不匹配 -- 那两条路本来就有闸, 只是没有窗口限速).
2. **间隔取 Beta(2,4)**: 众数 (2−1)/(2+4−2) = 1/4, 落回区间正是 3 + 12 × 1/4 = 6 秒;
   密度 ∝ x(1−x)³, 两端趋于零; 均值 7 秒, 中位约 6.76 秒.
   **采样用次序统计量, 不靠拒绝抽样**: 5 个均匀数里第 2 小的那个恰好服从 Beta(2,4)
   (第 k 个次序统计量 ~ Beta(k, n+1−k); k=2, n=5), 天然有界, 恰好五次 `random()`, 没有循环.
   每个随机数先夹进 [0,1], 非有限按 0(按最小间隔处理), 于是常数随机源 u 下第 2 小恒等于 u,
   固定随机的测试语义不变: `0 → 3000`, `1/4 → 6000`, `1/2 → 9000`, `1 → 15000`.
3. **等, 不拒**: 间隔不够就**等**够, 绝不拒绝, 绝不新增失败码. 调用方等完照发, agent 侧
   看不出差别.
4. **所有发送原语合成一条线**: `send.enter`, 发送态的圆键, `message.retry`, 看门狗催办的
   发送, 自动续聊的发送. 记的是"最近一次发送时刻", 与队列放行语义不同, **各记各的状态**,
   但合成一条线 -- 跨世界靠既有的 `window.postMessage` 通报时刻(`send-note`, 带 `world`
   字段, 两边都不认自己发的), 并的是**较晚**的那个时刻.
5. **"停止"永不延迟**: 圆键那一下可能是发送, 也可能是中断生成(class 一个不换, 只有图标
   `d` 换). 判出 `stop` 就不等; **判不出也不等** -- 宁可少限一次速, 也不能延迟一次中断.
6. **记发送比限速更保守**: 判不出意图的圆键点击照样记一笔"可能发出去了"; 宁可之后多等一次,
   也不漏记一次发送.
7. **全仓唯一一条限速**: 探针的动手节流(`scripts/page-action.py` 的 `pace`)并进同一条 --
   同一分布, 同一份规格(`protocol/fixtures/send-pace.json`, pytest 与 vitest 两半对拍);
   `--pace` / `--no-pace` 只剩人工排障的口子.
8. **跨世界的检查点是一个入口,两份实现**: `content.ts` 的 `paceRoster` 与
   `inject.content.ts` 的 `paceSend`, 都走 `sendpace.ts` 同一个 `checkSendIntent`.

## Considered Options

- **逐条发送 + 固定间隔**: 实测已证伪, 间隔合规照样撞限流. 否决.
- **让另两条路也排进出站口队列**: 真正统一的一条路, 但队列与窗口状态在 MAIN 世界, 另两条在
  隔离世界, 中间得过 background; 要的只是"别连发"这一条性质. 否决.
- **只在 background 侧限速**: MAIN 世界的续聊发送它看不见, 照样能与一次 `send.page` 连发.
  否决.
- **间隔不够就拒绝**(回 `disabled`): 给动作集加一个失败码, agent 侧要处理新的错误分支,
  而用户与 agent 都没做错什么 -- 只是发得急一点. 否决.
- **把圆键点击一律限速**(不判意图): 会把"停止"也延迟, 那是在延长一次用户明确要的中断. 否决.
- **用截断/夹取的 Beta 采样**(拒绝抽样或反函数 + 夹取): 夹取会在两个端点堆出概率尖刺,
  正好违背"两端趋于零". 否决.
- **把限速做成用户可配**: 默认值已经明确, 可配只多一个配置面与一套测试. 否决.
- **三态状态机(正常 / 长休 / 退避)**: 现在由退避闸独立承担, 不混进这道口.

## Consequences

- **单来回下队列恒只有一个元素**; 多块一轮(ADR-0005)时, 用户插话与在途回灌的顺序仍按队列
  先来后到.
- **一次 `send.page` 之后立刻续聊**, 续聊会等满剩下的间隔; 看门狗催办本就在静默期
  (15 分钟无动静)触发, 实际撞上间隔的概率极低.
- **跨世界多一条 `send-note` 消息**, 不落 `storage`, 不上 background -- 限速是当页行为,
  刷新后重新计时即可.
- **发送等待的最坏情形是 15 秒**(旧分布是 5 秒): 排探针与真机验收的时序余量按新上界算.
- **站点是否对单条消息长度另有判据**未实测; 合并后的消息更长, 这一条仍开着(见
  `docs/evidence/outbound-and-mutes.md`).

## 判据(怎么自己复现)

```sh
uv run pytest tests/test_send_pace.py -q          # 两半对拍同一份 send-pace.json
pnpm vitest run src/lib/outbound.test.ts src/lib/gate.test.ts

# 红(限速那格真是出站窗口撑着的): 把 src/lib/outbound.ts 抽样的那句改成 `const ratio = 0`,
# outbound.test.ts 与 gate.test.ts 当场 12 条红(25 条里 12 条); 而 pytest 那半照旧绿 --
# 它守的是两边共读那份 send-pace.json 的形状, 不是实现.
```

统计形状由带种子的单测钉住(脊背单调涨到 6 秒两格再单调落下, 最高两格必须是紧贴 6 秒的
那两格). 三次禁言的时间线与那 6 条回灌的间隔读数见 `docs/evidence/outbound-and-mutes.md`.
